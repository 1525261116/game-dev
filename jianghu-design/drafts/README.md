# 草案区（drafts）

> 存放**未定稿**的设计草案：新想法、待评审稿、实验性方案、多版本备选。

## 用途

- 新设计点先在这里成形，**讨论清楚后再并入对应编号模块**（`01_overview` ~ `10_ux`）。
- 存放同一设计的多套备选方案（如「方案A / 方案B」），便于对比取舍。
- 存放评审中被否决 / 暂缓的稿子（不删除，留痕可查）。

## 目录约定

- 命名：`YYYY-MM-DD_主题.md`（例：`2026-10-11_伙伴属性同深度方案.md`），便于按时间追溯。
- 每个草案文件开头建议标注状态：`状态：草案 / 待评审 / 已定稿（待并入 XX 模块）`。
- 定稿并入编号模块后，本目录保留原稿，并在文件顶部标注「已并入 → `0X_xxx/xxx.md`」。

## 与编号模块的区别

| 目录 | 定位 |
|------|------|
| `01_overview` ~ `10_ux` | **正式设计文档**（定稿、可交付、团队共识） |
| `drafts/` | **草案区**（未定稿、探索中、待评审） |
| `reference/` | 参考资料（原始策划案等，只读参考） |
| `templates/` | 文档模板 |
| `assets/` | 设计资源（参考图、原型图、概念图） |
