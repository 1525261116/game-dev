# 《江湖从心》动画复用方案：一套武学动画 × 多角色（N×M → N+M）

> 版本：v1.0｜日期：2026-10-11｜技术栈前提：TypeScript + Phaser 3
> 关联：[技术架构综合比较](技术架构综合比较_v1.0.md)｜[第 2 章 系统设计 · 功法系统](../GDD/02_系统设计.md)｜[第 4 章 关卡与内容规划 · 配置表契约](../GDD/04_关卡与内容规划.md)

---

## 0. 结论

**能解，而且必须解。** 核心思路只有一句：

> **把"动画"拆成三层，让「角色」和「功法」不再相乘，而是相加。**

```
最终战斗表现 = 角色皮肤层（每角色 1 套）
             + 动作层（每"武器类型" 1 组，全角色共用）
             + 功法特效层（每"特效原型" 1 套 + 参数化差异）
```

**资产数量对比（按 GDD 的真实内容量）**

| 做法 | 计算 | 资产数量 |
|------|------|:--------:|
| ❌ 朴素做法：每角色每功法单独做 | 87 功法 × 12 角色 | **1,044 套** |
| ✅ 三层做法 | 3 体型骨架 + 12 皮肤 + **56 个动作 clip** + ~16 个特效模板 | **≈ 87 项** |

**降 12 倍。** 而且新增一个角色（寻访令抽到新伙伴）只需**加一套皮肤（约 1~2 人日）**，不用碰任何动作。

## 1. 先算账：为什么不能"每套武学为每个角色单独设计"

按 [GDD 4.7.2](../GDD/04_关卡与内容规划.md) 的内容量：

| 项 | 数量 |
|----|------|
| 外功 6 类 × 11 门 | 66 |
| 内功 | 11 |
| 身法 | 10 |
| **功法合计** | **87** |
| 可培养角色（4 剧情伙伴 + 8 寻访伙伴） | 12 |
| 弟子模板（复用同一套角色表现） | 30 |
| 敌人（人形） | 数十 |

朴素做法的资产量：

```
87 功法 × 12 角色 × 每套 8 帧 = 8,352 张手绘图
```

**这是个人开发不可能完成的量级。** 而三层做法的资产量：

```
3 套体型骨架 + 12 套皮肤 + 56 个动作 clip + 16 个特效模板 ≈ 87 项
```

## 2. 四个可选方案

### 方案 A · 骨骼动画 + 换肤（Spine / DragonBones）

**原理**：所有人类角色共用**同一副骨架**（统一骨骼与 slot 命名），角色差异用 **skin（贴图替换）** 表达，功法差异用**同一骨架上的不同动画 clip** 表达。这是 2D 行业的标准解法——Spine 官方论坛专门有 "Skins for Template"、"character customiser"（角色自定义）的成熟工作流（[Spine 官方论坛 · 自定义角色](https://hr.esotericsoftware.com/forum/d/30235-advice-on-best-way-to-setup-character-customiser/5)、[Skins for Template](https://vi.esotericsoftware.com/forum/d/29845-help-regarding-skins-for-template/2)）。

| 项 | 评估 |
|----|------|
| 资产量 | N 皮肤 + M clip —— **最优** |
| Phaser 支持 | **官方支持**：`SpineGameObject`（[Phaser 文档](https://docs.phaser.io/phaser-editor/scene-editor/game-objects/spine-game-object)）；Phaser 3.19 起内置 Spine 插件 |
| 水墨适配 | 中——骨骼形变容易"橡皮感"，需要美术专门为形变作画 |
| 授权成本 | Spine 为商业授权（[官方购买页](https://zh.esotericsoftware.com/spine-purchase)，⚠️ 价格未核验；通常分 Essential/Professional/Enterprise 档，Runtime 授权另有条款） |
| DragonBones | 免费，但社区出现"寻找 DragonBones 替代品""把老 DragonBones 转成 Spine 格式"的讨论（[Defold 论坛](https://forum.defold.com/t/db-reborn-convert-old-dragonbones-json-to-spinejson-files/82479/8)、[RPG Maker 论坛](https://forums.rpgmakerweb.com/threads/substitute-plugins-for-dragonbone.177767/)），**维护活跃度存疑 🟡** |
| AI 可操作性 | 差——动画在 GUI 编辑器里制作，AI 无法操作，也无法批量生成 |
| 结论 | 效果最好、成本最高；**更适合后期做少量高光角色（BOSS、剧情演出）** |

### 方案 B · 帧动画 + 武器动作组（不引入骨骼）

**原理**：动作由**武器类型**决定，而不是由功法决定。

- 全游戏只有 **6 组武器动作**（刀 / 剑 / 拳掌 / 暗器 / 奇门 / 枪）+ 内功组 + 身法组
- 每个角色 = 一套身体帧动画（挂在同一套动作节点上）
- **功法之间的差异由「特效 + 时序 + 音效 + 命中停顿」承载，不由动作承载**

| 项 | 评估 |
|----|------|
| 资产量 | 6 组动作 × 8 帧 + 角色身体帧 —— 比朴素做法省 10 倍以上 |
| Phaser 支持 | 原生（SpriteSheet + Animation），零依赖 |
| 水墨适配 | **最好**——逐帧手绘是水墨观感的最优解 |
| 授权成本 | 0 |
| AI 可操作性 | 中——帧图要美术画，但**动画配置与播放逻辑是纯 TS** |
| 风险 | 每角色仍要画 6 组×8 帧 = 48 帧身体动作；12 角色 = 576 帧（量仍偏大，但可接受） |
| 结论 | **如果美术坚持逐帧手绘，就选它**；用"统一动作节点 + 角色帧图"的约定来共享动作节奏 |

### 方案 C · 自研轻量 cutout 骨骼（JSON 时间轴驱动）★ 推荐

**原理**：把角色拆成**部件贴图**（头 / 躯干 / 上臂 / 前臂 / 手 / 腿 / 武器 / 披风），用 Phaser 的 `Container` + 部件 `Sprite` 组成 rig；动作 = **纯 JSON 的关键帧数据**（每个部件在时间点上的位移/旋转/缩放/层级）。角色差异 = 换部件贴图；功法差异 = 换 clip + 特效。

| 项 | 评估 |
|----|------|
| 资产量 | 部件贴图（每角色 1 套，比整套帧动画少得多）+ M clip —— **接近方案 A** |
| Phaser 支持 | 原生能力即可（Container / Sprite / Tween / RenderTexture），**无需第三方插件** |
| 水墨适配 | **极好**——剪纸/皮影/纸片人风格与水墨天然契合（墨迹虚边 + 纸感）。中国风的"皮影戏"正是这个技术 |
| 授权成本 | **0** |
| AI 可操作性 | **最优**——动作数据是纯 JSON/TS 文本，我可以批量生成、调参、校验；播放器代码我直接写 |
| 动画编辑器 | **Web 栈红利**：我可以给你写一个浏览器内时间轴编辑器（比在 Unity 里配 Animator 更可控，且我能改） |
| 风险 | 需要自研一层运行时（约 300~500 行 TS）+ 美术要按部件拆分作画 |
| 结论 | ✅ **本项目的首选** |

### 方案 D · 单套动画 + 调色板/VFX 变体

**原理**：所有角色所有功法共用一套动作，只换颜色和特效。
**优点**：几乎零成本。**缺点**：辨识度极低，玩家会觉得"打什么都一样"。
**结论**：不做主方案，但可作为**方案 C 的降级兜底**（某个功法没来得及做专属表现时先用通用表现顶上，绝不阻塞开发）。

---

## 3. 推荐：方案 C 为主，方案 B 为兜底

| 选择 | 理由 |
|------|------|
| **主选 C（自研 cutout）** | ① 资产量最低；② 授权为 0；③ **动作数据是文本 → AI 能生成、能批量调、能校验**，这是 vibe coding 工作流的核心红利；④ 剪纸/墨迹风格与水墨契合；⑤ Phaser 原生能力就够，不加依赖 |
| 兜底 B（帧动画） | 若美术最终坚持逐帧手绘，用"武器动作组"约定同样能达到共享目的，只是资产更多 |
| 局部 A（Spine） | 后期若要给 BOSS / 剧情演出做高光动作，可只对 2~3 个角色引入 Spine，不影响全局架构 |
| 保底 D | 未完成表现的功法先用通用动作 + 特效顶上 |

## 4. 三层架构的具体设计

### 4.1 第 1 层：骨架与 slot 命名规范（**这是成败关键**）

所有人类角色必须能挂到**同一副骨架拓扑**上。体型差异用**缩放与骨骼长度参数**实现，不用新骨架。

```
统一 slot 命名（所有角色必须一致，否则无法换肤）：
  head        头
  torso       躯干
  upperArmL / forearmL / handL     左臂三段
  upperArmR / forearmR / handR     右臂三段
  thighL / shinL / footL           左腿三段
  thighR / shinR / footR           右腿三段
  cloak       披风（可选）
  weapon      武器挂点（必填，空手时为 null）
  aura        气劲挂点（内功/身法特效用）

体型预设（3 套，不是每角色一套）：
  body_male_adult     成年男
  body_female_adult   成年女
  body_burly          魁梧（BOSS/壮汉）
```

> **硬规则**：新增角色时**只允许新增贴图，不允许新增 slot**。违反这条，换肤体系立刻崩塌。

### 4.2 第 2 层：角色皮肤包

每个角色一个目录，结构完全一致：

```
assets/chars/char_xiejiu/
  skin.json          # 每个 slot → 图集帧名映射
  atlas.png / atlas.json   # 该角色所有部件贴图
  palette.json       # 可选：调色板（用于变色变体，如精英怪复用同一套图）
```

**新增一个伙伴的成本 = 1 套部件贴图 + 1 个 skin.json（约 1~2 人日）**，动作与特效全部继承。

### 4.3 第 3 层：动作库（按武器类型分组，全角色共用）

**动作数量 = 武器类型 × 动作原型，与角色数无关。**

| 动作组 | 动作原型（8 个） |
|--------|------------------|
| 刀 / 剑 / 拳掌 / 暗器 / 奇门 / 枪（各 8 个） | `idle` 待机 · `ready` 起势 · `atk_a` 快招 · `atk_b` 重击 · `cast` 功法起手 · `hit` 受击 · `dodge` 闪避 · `down` 倒地 |
| 内功组（4 个） | `idle` · `meditate` 打坐运气 · `cast` 内劲外放 · `aura` 持续气劲 |
| 身法组（4 个） | `dash` 疾冲 · `leap` 腾挪 · `vanish` 残影消失 · `land` 落地 |

**合计 6×8 + 4 + 4 = 56 个 clip**。每个 clip 只做一次，**12 个角色共用**。

### 4.4 第 4 层：功法视觉映射（**功法只描述"差异"，不描述"动作"**）

这是把 87 门功法压到 16 个特效模板的关键。

```ts
// data/gongfa_visual.ts —— 87 门功法的表现定义，每行一条
export interface GongfaVisual {
  id: string;              // 功法 ID
  motionGroup: MotionGroup; // dao|jian|quan|anqi|qimen|qiang|neigong|shenfa
  motion: MotionId;         // 动作原型：cast|atk_a|atk_b|...
  vfx: VfxId;               // 特效模板（16 选 1）
  timingScale: number;      // 时序倍率 0.8~1.4（重击慢、快招快）
  hitStopMs: number;        // 命中停顿 0~120ms
  shake: 0 | 1 | 2;         // 屏幕震动 无/轻/重
  sfx: SfxId;               // 音效模板 + 音高偏移
  colorByQuality: true;     // 颜色由品质决定（见下）
  targets: 'single' | 'column' | 'row' | 'all'; // 决定特效范围与形状
}
```

**品质直接决定特效颜色**（玩家一眼看出功法档次，且零额外成本）：

| 品质 | 主色 | 附加 |
|------|------|------|
| 凡品 | 灰白 | 朴素粒子 |
| 良品 | 青碧 | + 轻微拖尾 |
| 上品 | 靛蓝 | + 拖尾 + 光晕 |
| 极品 | 暗金 | + 拖尾 + 光晕 + 残影 |
| 绝世 | 赤金 | + 全屏闪 + 墨迹扩散 + 镜头轻推 |

**示例映射（用你已有的功法）**

| 功法 | 动作组 | 动作原型 | 特效模板 | 时序 | 命中停顿 | 备注 |
|------|--------|----------|----------|:----:|:--------:|------|
| 狂风刀法 | 刀 | `cast` | `slash_arc` | ×1.15 | 40ms | 追加一次 → 播两遍 |
| 断岳刀法 | 刀 | `atk_b` | `slash_heavy` | ×0.85 | 90ms | 慢而重 + 重震屏 |
| 霸刀 | 刀 | `atk_b` | `slash_heavy` | ×0.75 | 120ms | 同模板，加大尺寸/颜色/全屏闪 |
| 流云剑法 | 剑 | `atk_a` | `thrust_multi` | ×1.3 | 30ms | 连击 +1 → 三段连播 |
| 落霞剑法 | 剑 | `cast` | `slash_arc` | ×1.0 | 50ms | 换色（晚霞红） |
| 罗汉拳 | 拳掌 | `atk_a` | `palm_wave` | ×1.0 | 60ms | 眩晕 → 头顶星环 |
| 太极拳 | 拳掌 | `cast` | `aura_ring` | ×1.2 | 30ms | 环形气劲 |
| 柳叶刀 | 暗器 | `atk_a` | `missile_thin` | ×1.35 | 20ms | 必中 → 命中标记 |
| 暴雨梨花针 | 暗器 | `cast` | `missile_multi` | ×1.1 | 40ms | 多发散射 |
| 判官笔 | 奇门 | `atk_a` | `qimen_rune` | ×1.0 | 45ms | 封穴 → 穴位符文 |
| 生死符 | 奇门 | `cast` | `qimen_rune` | ×1.25 | 60ms | 同模板换色 + 冰晶 |
| 杨家枪法 | 枪 | `atk_a` | `sweep_row` | ×1.0 | 50ms | 范围横扫（打整排） |
| 回马枪 | 枪 | `atk_b` | `thrust_pierce` | ×0.9 | 80ms | 击退 → 位移表现 |
| 基础内功 | 内功 | `aura` | `aura_body` | ×1.0 | 0ms | 持续气劲 |
| （任意身法） | 身法 | `dash` | `afterimage` | ×1.0 | 0ms | 残影拖尾 |

> **连招加成叠加**：二连 / 三连成功时，在特效层**叠加**额外表现（拖尾增强、颜色变亮、追加墨迹爆点），威力加成已经有数值（+30% / +60%），表现要同步放大——这让"连招成功"成为**看得见的爽点**。

### 4.5 挂点（anchor）：让特效与动作解耦

每个动作 clip 里声明挂点位置（可由编辑器导出）：

| 挂点 | 用途 | 由谁提供 |
|------|------|----------|
| `weaponTip` | 斩击/突刺/枪击的起点与方向 | 动作 clip |
| `palm` | 掌风/气劲的发射点 | 动作 clip |
| `throwPoint` | 暗器掷出点 | 动作 clip |
| `bodyCenter` | 环形气劲/护体光 | 骨架 |
| `footPoint` | 位移残影/落地墨点 | 骨架 |
| `hitPoint` | 命中特效落点（由战斗逻辑给出目标） | 战斗结果 |

**特效不依赖具体动作名，只依赖挂点**，所以新增动作时特效无需改动。

## 5. Phaser + TS 实现骨架

### 5.1 目录结构

```
src/
  core/                       # 纯逻辑，无 Phaser 依赖（可 vitest 测试）
    battle/                   # 战斗预结算（GDD 5.4）
    formula/                  # 伤害公式
  render/                     # 表现层
    anim/
      Rig.ts                  # cutout 骨架：Container + 部件 Sprite
      MotionPlayer.ts         # 播放 JSON 时间轴 clip
      MotionLib.ts            # clip 注册表（56 个）
      SkinRegistry.ts         # 角色皮肤注册表（12+ 套）
      VfxLayer.ts             # 特效层（独立于角色，按挂点定位）
      VfxFactory.ts           # 16 个特效模板 + 参数化
    battle/
      BattleView.ts           # 九宫格布阵与战斗表现
      HitStop.ts              # 命中停顿 / 震屏 / 镜头
assets/
  rigs/humanoid/              # 骨架定义（3 体型参数）
  motions/{dao,jian,quan,anqi,qimen,qiang,neigong,shenfa}/*.json
  chars/<charId>/{skin.json,atlas.png,atlas.json}
  vfx/*.json
data/
  gongfa_visual.ts            # 87 行功法表现映射
```

### 5.2 播放流程（4 步，全自动战斗里每回合调用一次）

```ts
class CharacterAnimator {
  play(visual: GongfaVisual, ctx: { owner: UnitView; targets: UnitView[] }) {
    // ① 皮肤：换部件贴图（角色差异）
    this.rig.applySkin(SkinRegistry.get(ctx.owner.charId));

    // ② 武器：按武器类型挂对应武器图（同角色可换兵器）
    this.rig.setAttachment('weapon', WeaponFrames.of(ctx.owner.charId, visual.motionGroup));

    // ③ 动作：播放**全角色共用**的 clip，按功法时序倍率变速
    this.player.play(visual.motion, {
      group: visual.motionGroup,
      timeScale: visual.timingScale,
      onAnchor: (name, worldPos) => {
        // ④ 特效：在动作提供的挂点上生成（功法差异）
        if (name === 'weaponTip' || name === 'palm' || name === 'throwPoint') {
          VfxFactory.spawn(visual.vfx, worldPos, {
            color: colorOfQuality(visual.quality),
            targets: visual.targets,
            comboLevel: ctx.comboLevel,   // 连招层级 → 叠加表现
          });
        }
      },
    });

    HitStop.apply(visual.hitStopMs, visual.shake);
    Sfx.play(visual.sfx, { pitch: qualityPitch(visual.quality) });
  }
}
```

### 5.3 性能要点（对 GDD 5.4 技术预算负责）

| 要点 | 做法 |
|------|------|
| 同屏人数 | 九宫格最多 4v4（门派战 5v5+）→ 同时活跃 rig ≤ 10 |
| 部件数 | 每 rig 约 12~14 个 Sprite → 同屏 ~140 个 Sprite，Phaser 无压力 |
| 图集 | 每角色部件打一张 ≤ 2048² 图集；同屏最多加载当前参战角色（≤10 张） |
| 对象池 | 所有部件 Sprite、特效粒子、飘字走对象池 |
| 战斗表现与逻辑分离 | **战斗先算完**（GDD 5.4 强制要求），表现层按结果回放；支持 1×/2×/4×/跳过 |
| 低端机降级 | 关闭残影/全屏闪/粒子数减半，仅保留动作 + 基础特效 |
| 确定性 | 表现层**不参与任何数值计算**，只读结果 → 不影响"同种子同结果" |

## 6. 收益与工时对比

| 资产项 | 朴素做法 | 三层做法 | 节省 |
|--------|:--------:|:--------:|:----:|
| 体型骨架 | — | 3 | — |
| 角色皮肤 | 12 × 8 帧 × 6 组 = 576 帧 | **12 套部件皮肤** | ~5× |
| 动作 clip | 1,044 套 | **56 个** | **~19×** |
| 功法特效 | 1,044 套 | **16 个模板 + 参数** | **~65×** |
| 新增 1 个角色 | 87 套动画 | **1 套皮肤（1~2 人日）** | ~50× |
| 新增 1 门功法 | 12 套动画 | **1 行映射 + 复用特效** | ~12× |

> **注意最后两行**：这是一个**复利**结构——游戏上线后每加一个角色/一门功法，成本几乎不变。这决定了项目能否长线更新（GDD 5.8 的 DLC 计划依赖这一点）。

## 8. 风险与对策

| # | 风险 | 对策 |
|---|------|------|
| 1 | cutout 的"橡皮感"破坏水墨观感 | ① 部件边缘做**墨迹虚边 + 纸纹**；② 角度变化限制在 ±25°；③ 关键动作（大招）插 2~3 张手绘帧补足 |
| 2 | "所有功法看起来一样" | 靠**品质配色 + 特效形状 + 时序 + 命中停顿 + 震屏 + 音效**六项差异化（§4.4）；连招叠加表现 |
| 3 | slot 规范被破坏（有人给新角色加了部件） | 写**自动校验脚本**：加载 skin.json 时校验 slot 集合是否为规范子集，缺 slot 用占位图兜底并报警 |
| 4 | 自研运行时需要维护 | 纯 TS + 单元测试（我可以跑 vitest 验证），且不依赖第三方插件，不受引擎政策影响 |
| 5 | 美术不接受"拆部件作画" | 启用兜底**方案 B（帧动画 + 武器动作组）**——同样能达到共享目的，只是资产更多 |
| 6 | 表现层拖慢低端机 | 分级降级开关（§5.3）；表现层与逻辑完全分离，可一键"极简模式" |

## 10. 一句话总结

**不要做"每套武学 × 每个角色的动画"，要做"一套骨架 + 一套动作组 + 一张角色皮肤 + 一套特效参数"。**
角色换皮，功法换特效与节奏，动作全角色共用——**新增角色只需 1~2 人日，新增功法只需改 1 行映射**。
在 Phaser + TS 下这套架构**不需要任何第三方插件**（Container + Sprite + 自定义 JSON 时间轴即可），而且因为一切是文本，**我能直接生成、调参、校验，并给你写一个浏览器内的动画编辑器**。
