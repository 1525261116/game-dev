## 1. 项目约束与技术选型结论

### 1.1 约束（来自你的实际情况）

| # | 约束 | 影响 |
|:-:|------|------|
| 1 | **开发者为 1 人 + AI**，vibe coding 工作流 | 选型第一权重 = "AI 能否独立运行与验证" |
| 2 | 目标双端：移动端（iOS/Android）+ PC | 需要一套代码多端产出 |
| 3 | 2.5D 斜视角水墨武侠 | 表现形态需与个人产能匹配（见 D2） |
| 4 | 内容量驱动：24 张配置表 / ≈7,100 行 / 87 功法 / 80 奇遇 | 数据管线与内容复用是胜负手 |
| 5 | 一周目 20~25 小时（精简版基线） | 内容生产是长周期主项 |
| 6 | 商业化为双轨定价（PC 买断 + 移动免费本体 + 纯外观/剧情/便利） | 需要 Steam + StoreKit/Google Play 支付路径 |
| 7 | 国内版号周期不可控 | **PC/Steam 先行**是主路径 |

### 1.2 选型结论

| 层 | 选型 | 备选 | 切换触发条件 |
|----|------|------|--------------|
| 引擎 | **Phaser 3.x（锁定小版本）** | Unity 6.x LTS | 真机 WebView 无法 30FPS / 必须真 2.5D 动态光照 / 必须上主机 / 必须国内安卓多渠道内购 |
| 语言 | **TypeScript 5.x（strict）** | — | — |
| 构建 | **Vite** | — | — |
| 打包（PC） | **Electron**（+ steamworks.js） | Tauri 2 | Electron 体积/性能不可接受 |
| 打包（移动） | **Capacitor 8.x** | — | — |
| 测试 | **Vitest**（逻辑）+ **Playwright / 本机 Chrome 无头**（表现截图） | — | — |
| 数据校验 | **zod** | — | — |
| 动画 | **自研轻量 cutout 骨骼**（方案 C） | 帧动画 + 武器动作组 | 美术不接受拆部件作画 |

> **选型一句话**：不是"Phaser 比 Unity 强"，而是**在"AI 写代码"这个前提下，唯一能被 AI 自己跑起来、截图验证、批量生成数据的技术栈胜出**；Unity 的优势（2.5D 光照、移动性能、商业化成熟度）在 D2 采用「剪纸小人 + 烘焙光照」、且移动端不作为首发重点后，全部不成立。

## 2. 总体架构

### 2.1 分层架构（铁律：上层依赖下层，反向禁止）

**分层架构（自上而下）**

| 顺序 | 层级 | 包含内容 | 职责 |
|:----:|------|----------|------|
| 1 | 平台层 Platform | Web / PWA ｜ Electron(PC·Steam) ｜ Capacitor(iOS·Android) | 窗口、文件、云存档、支付、成就、真机适配 |
| 2 | 表现层 Render（Phaser） | 场景管理 ｜ 九宫格战斗表现 ｜ UI ｜ 动画(方案C) ｜ 音频 ｜ 特效 | 把「事件流」翻译成画面与声音；不含任何数值判断 |
| 3 | 逻辑层 Core（纯 TS，禁止 import phaser） | 战斗预结算 ｜ 伤害公式 ｜ 成长/境界/修为 ｜ 伙伴 ｜ 门派 ｜ 任务 ｜ 奇遇 ｜ 经济 ｜ 掉落 ｜ 存档 ｜ 图鉴 ｜ 可播种 RNG | — |
| 4 | 数据层 Data | CSV/Excel → 导出脚本 → JSON + zod schema → 校验 → 加载 | — |
| 5 | 工具层 Tools（Node 脚本 + 浏览器内编辑器） | 导出 ｜ 校验 ｜ 战斗模拟器 ｜ 掉落模拟器 ｜ 时间轴动画编辑器 | — |

**层间耦合（图中箭头均朝上一层方向 ▲）**

| 相邻层 | 耦合说明 |
|--------|----------|
| 平台层 ↔ 表现层 | PlatformAdapter 接口（唯一耦合点） |
| 表现层 ↔ 逻辑层 | 只读：BattleEvent[] / GameState 快照 |
| 逻辑层 ↔ 数据层 | 只读：DataRegistry（已校验的配置数据） |
| 数据层 ↔ 工具层 | （无标注） |

### 2.2 五条架构铁律（可自动检查）

| # | 铁律 | 强制手段 |
|:-:|------|----------|
| 1 | **Core 不得 import Phaser / 任何渲染库** | ESLint `no-restricted-imports`，CI 失败即阻断 |
| 2 | **战斗先算完，表现后回放**（预结算 + 表现分离） | 接口只暴露 `BattleEvent[]`，表现层无副作用 |
| 3 | **一切内容来自配置表**，代码零硬编码 | 代码里出现功法名/道具名即 review 不通过 |
| 4 | **存档引擎无关**（JSON + zod + 迁移函数） | 迁移测试用例覆盖前 3 个版本 |
| 5 | **所有随机走可播种 RNG**，禁止 `Math.random()` | ESLint `no-restricted-globals` + 同种子同结果测试 |

## 3. 模块设计

### 3.1 核心逻辑层（Core）—— 纯函数优先

| 模块 | 关键接口（示意） | 对应 GDD |
|------|------------------|----------|
| `battle/simulate` | `simulate(setup: BattleSetup, rng: Rng): BattleResult` | 2.1 / 5.4 |
| `formula/damage` | `computeDamage(attacker, defender, skill, ctx): DamageResult` | 3.1.2 |
| `progression/realm` | `canBreakthrough(state): Resource[] / applyBreakthrough()` | 3.3 |
| `progression/cultivation` | `addCultivation(type, quality, tier)`（按类型累计） | 3.4.3 |
| `gongfa/combo` | `resolveCombo(slots[5]): ComboChain` | 2.4 / 3.4.5 |
| `quest/trigger` | `evalTrigger(encounter, state): boolean` | 2.9 |
| `save/migrate` | `migrate(raw: unknown, from: number): SaveV3` | 2.13 |
| `world/time` | `advance(time, hours): GameTime` | 3.7 |

**设计原则**：每个函数都是**纯函数或显式传入状态**，不读全局、不读 Phaser、不读时间。这样我可以用 vitest 跑 1000 次并断言分布。

### 3.2 数据与配置管线（内容量的生命线）

配置/数据管线流程如下：

1. 设计表（CSV / Excel，策划可编辑）。
2. 经 `tools/import-tables.ts` 转换为 JSON（`tables/*.json`）。
3. 经 zod schema 校验，校验包含 5 项：
   - ① 引用完整性（所有 id 存在）
   - ② 概率和 ≤ 100%
   - ③ 数值边界（暴击≤75%、闪避≤60%、命中5~95%…）
   - ④ 单调性（经验曲线、境界倍率、装备基准递增）
   - ⑤ 经济闭合（每件物品 ≥1 个消耗去向）
4. 进入 DataRegistry（运行时只读，全量加载目标 < 200ms）。

**统一口径**：`id` 全局唯一带前缀（`GF_` 功法 / `EQ_` 装备 / `ENC_` 奇遇 / `IT_` 道具 / `MO_` 动作 / `VFX_` 特效）。

**目标（写进验收）**：**改一行配置 → 游戏内生效，全程 < 10 分钟，无需程序介入**（GDD 5.2 Gate 3）。

### 3.3 表现层（Render）

| 子模块 | 职责 | 关键设计 |
|--------|------|----------|
| `scenes/Boot` | 资源分包加载、进度条、错误兜底 | 首包只含 UI + 序章 |
| `scenes/WorldMap` | 大地图节点选择（**不做自动寻路**） | 只标区域，不标点位（GDD 2.9） |
| `scenes/Scene` | 小场景点击式探索、可交互点、奇遇触发 | 场景由模块拼装（GDD 4.7.3） |
| `scenes/Battle` | 九宫格布阵 → 事件回放 → 结算 | 支持 1×/2×/4×/跳过；跳过=直接设结果 |
| `battle/EventPlayer` | 把 `BattleEvent[]` 按时间轴回放 | 表现层零数值判断 |
| `battle/Formation` | 9 格拖拽、连招链路预览、词条高亮 | 唯一强操作点（GDD 2.1） |

### 3.4 动画系统（方案 C 摘要）

> 详细规范见 [动画复用方案](动画复用方案_v1.0.md) 与 [方案 C 实施方案](方案C_实施方案与分工估算_v1.0.md)。

| 项 | 设计 |
|----|------|
| 三层架构 | 角色皮肤层 + 动作层（按武器类型，56 clip 全角色共用）+ 功法特效层（16 模板 + 参数） |
| 资产量 | 1,044 套 → **≈87 项**；新增角色 = 1 套皮肤（1~2 人日）；新增功法 = 1 行映射（10 分钟） |
| 骨架 | **统一 slot 命名**（head/torso/upperArmL…/weapon/aura），只允许新增贴图、**不允许新增 slot** |
| 体型 | 3 套预设（成年男 / 成年女 / 魁梧），用骨骼长度与缩放表达差异 |
| 动作数据 | JSON 时间轴（关键帧 8~14 个/部件；4 种缓动；统一 100ms 过渡） |
| 挂点 | `weaponTip` / `palm` / `throwPoint` / `bodyCenter` / `footPoint` / `hitPoint` |
| 功法差异化 | 特效形状 + **品质配色**（凡灰白→良青碧→上靛蓝→极暗金→绝赤金）+ 时序倍率 + 命中停顿 + 震屏 + 音效 |
| 连招叠加 | 二连加拖尾、三连叠墨迹爆点 + 震屏加强（让 +30%/+60% 看得见） |
| 武器贴图 | **按「类型 × 品质」共享：30 张覆盖全游戏**（同时是外观付费切入点） |
| 编辑器 | 浏览器内时间轴编辑器（我可以写）——**编辑器优先于内容**，否则每次改动作都要我介入 |

### 3.5 存档系统

| 项 | 设计 |
|----|------|
| 格式 | 引擎无关 JSON + zod 校验字段 + `version` |
| 迁移 | `migrate(raw, from) → latest`，覆盖前 3 个大版本，有测试用例 |
| 槽位 | 自动 3 槽（轮转）+ 手动 3 槽；触发点见 GDD 2.13 |
| 存储 | Web: IndexedDB ｜ Capacitor: Filesystem ｜ Electron: 用户目录 + Steam Cloud |
| 跨端 | 天然互通（同一份 JSON）；提供"存档码"导出/导入 |
| 大小 | ≤ 2MB（不含截图） |
| 崩溃保护 | 写入采用"临时文件 + 原子替换"，避免半写损坏 |

### 3.6 平台适配层

`PlatformAdapter` 接口字段如下：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `'web' \| 'electron' \| 'capacitor'` | 平台标识 |
| `storage` | `{ read(k): Promise<string\|null>; write(k, v): Promise<void> }` | 键值存储 |
| `fs?` | `{ readBinary(p): Promise<Uint8Array> }` | 桌面/移动 |
| `cloud?` | `{ save(slot, data): Promise<void>; load(slot): Promise<string\|null> }` | 云存档 |
| `achievement?` | `{ unlock(id: string): void }` | 成就 |
| `iap?` | `{ purchase(sku: string): Promise<Receipt>; restore(): Promise<Receipt[]> }` | 内购 |
| `safeArea()` | `{ top: number; bottom: number; left: number; right: number }` | 安全区 |
| `haptics?` | `(style: 'light' \| 'medium' \| 'heavy'): void` | 触感反馈 |
| `lifecycle` | `{ onPause(cb): void; onResume(cb): void }` | 生命周期 |

| 实现 | 目标 | 关键点 |
|------|------|--------|
| `web.ts` | 浏览器 / PWA / Demo | IndexedDB；无 IAP |
| `electron.ts` | Windows / macOS / Linux / Steam | 文件系统；steamworks.js 接成就 + 云存档；Overlay 验证 |
| `capacitor.ts` | iOS / Android | Filesystem + SafeArea + IAP 插件 + 生命周期暂停 |

| # | 议题 | 方案 |
|:-:|------|------|
| 1 | **确定性** | Core 内所有数值走**定点数**（整数 ×1000），随机走可播种 RNG；禁止 `Math.random()` 与浮点比较；跨端同种子同结果有测试用例 |
| 2 | **战斗性能** | 预结算 < 50ms（4v4 / 30 回合）；表现层与逻辑分离，跳过时零播放开销 |
| 3 | **等距投影** | `screenX = ox + (col-row)*TW/2`；`screenY = oy + (col+row)*TH/2 - h`；渲染层级 = `(col+row)` 升序 |
| 4 | **对象池** | 部件 Sprite / 特效粒子 / 飘字 / 伤害数字全部池化；战斗结束零 GC 峰值 |
| 5 | **资源分包** | 首包 = UI + 序章 + 核心图集；按区域/角色分包按需加载；图集 ≤2048² 且离场卸载 |
| 6 | **表现分级** | 低/中/高三档：低档关残影、粒子减半、关全屏闪、降帧率；由 `settings.quality` 驱动 |
| 7 | **本地化** | 全文本 ID 化，`text.csv` 外链；单条支线 ≤2,500 字（控成本） |
| 8 | **音频** | Phaser Sound 足够；音乐按场景切换 + 淡入淡出；移动端切后台静音 |
| 9 | **错误处理** | 全局 error boundary → 控制台 + 本地错误日志；配置缺失走**占位兜底**（绝不崩溃） |
| 10 | **热更** | 静态资源版本化 + 资源清单 hash；**不做代码热更**（降低 iOS 合规风险） |
