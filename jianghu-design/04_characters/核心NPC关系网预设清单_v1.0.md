# 核心NPC关系网预设清单 v1.0

> **定位**：按角色通用模型 §14.4 定案（NPC×NPC 不实时演算，预设关系网由剧情 / 奇遇触发插入双方 lifeEvents），设计核心 NPC（150~250）的预设关系系统——关系类型、数据结构、触发机制、密度基准与示例关系网。
> **关联**：角色通用模型见 [`角色通用模型与NPC动态系统_v1.0.md`](角色通用模型与NPC动态系统_v1.0.md) §8 / §14.4；势力框架见 [`../02_worldbuilding/势力框架.md`](../02_worldbuilding/势力框架.md)；门派养成见 [`../06_systems/门派养成.md`](../06_systems/门派养成.md)；伙伴列表见 [`伙伴系统/伙伴列表/伙伴列表.md`](伙伴系统/伙伴列表/伙伴列表.md)。

## 一、设计目标与口径

### 1.1 设计目标

> 让江湖**有人情味**——核心 NPC 之间不是孤立的木桩，而是有师承、有恩怨、有同门、有情缘的活关系网。玩家介入这些关系（救其师、杀其敌、断其缘）会产生涟漪效应，制造查案 / 结交 / 探究的叙事钩子。

### 1.2 口径来源（已定案）

| 项 | 定案 | 来源 |
|----|------|------|
| 实时演算 | **不做**（太重且易生荒诞剧情） | 角色通用模型 §14.4 |
| 关系网 | 预设——师徒 / 宿敌 / 同门 / 情缘四类 | 角色通用模型 §14.4 |
| 触发方式 | 剧情脚本 / 奇遇触发，插入双方 lifeEvents | 角色通用模型 §14.4 |
| 玩家介入 | 可改变预设关系（救其师、杀其敌、断其缘） | 角色通用模型 §14.4 |
| 适用范围 | 仅核心 NPC（150~250）；背景路人不交互 | 角色通用模型 §14.4 / §14.1 |

## 二、关系类型定义（四类）

### 2.1 四类关系总览

| 关系类型 | 方向性 | 典型 delta | 玩家介入钩子 |
|----------|--------|------------|--------------|
| **师徒** master-disciple | 单向（师→徒） | 徒弟功法 source=门派传授/师承多门、徒弟境界受师父提携 | 救其师则徒感恩、杀其师则徒复仇 |
| **宿敌** nemesis | 双向（互敌） | 双方 morality 互降、关系标签"宿敌"、见面可能触发战斗 | 助其敌则结仇、调解两敌可化干戈 |
| **同门** fellow | 双向（同源） | 共同 factionId、功法来源同门派、互相指点加成 | 离间同门可瓦解门派、团结同门可聚力 |
| **情缘** bondmate | 双向（互慕） | 好感度互提、特殊对话、可能触发剧情分支 | 断其缘则反目、成其缘则结盟 |

### 2.2 关系强度分级

> 每类关系有强度，影响触发频率与介入难度。

| 强度 | 等级 | 说明 |
|------|------|------|
| 弱 | 1 | 点头之交 / 远房同门，偶有互动 |
| 中 | 2 | 稳定关系，剧情会提及 |
| 强 | 3 | 深度绑定，玩家介入会触发显著分支 |

## 三、Relationship 数据结构

> 每条预设关系是一个 Relationship 实例，存于双方 Character 的 lifeEvents 与一个全局关系表中。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 关系唯一标识 |
| type | master-disciple / nemesis / fellow / bondmate | 关系类型 |
| partyA | string | NPC A 的 id |
| partyB | string | NPC B 的 id（师徒关系中 A=师、B=徒） |
| strength | 1~3 | 关系强度 |
| origin | string | 关系起源（游戏时间锚点 + 简述） |
| status | active / broken / frozen | 当前状态（活跃 / 已断 / 冻结） |
| triggerEvent | string | 触发该关系的剧情 / 奇遇事件 id |
| flags | 标签集 | 是否玩家介入过、是否关键节点等 |

> **存储原则**：关系既存于全局关系表（供剧情脚本查询），也以 feud / grace / betray 等 lifeEvent 形式回写到双方传记——保证 NPC 状态可由「初始资质 + 传记事件序列」完整重建（角色通用模型 §8.3）。

## 四、触发机制

### 4.1 预设关系的三种触发时机

| 时机 | 触发方 | 典型场景 |
|------|--------|----------|
| **初始传记生成时** | NPC 配置导入期 | 师徒关系在 NPC 生成时即写入传记（"自幼拜入张三丰门下"） |
| **剧情节点推进时** | 主线 / 支线脚本 | 阶段3 立场抉择后，陆青崖与凌云阁掌门关系由"同门"转为"宿敌" |
| **奇遇触发时** | 奇遇事件 | 玩家在青城山奇遇中救下某 NPC，触发他与宿敌的 grace 事件 |

### 4.2 关系事件如何插入 lifeEvents

> 关系触发时，向**双方** lifeEvents 各插入一条事件，保证状态对称。

| 步骤 | 规则 |
|------|------|
| 1. 判定触发 | 剧情脚本 / 奇遇判定条件满足（声望 / 伙伴携带 / 时间 / 福缘） |
| 2. 构造事件 | 生成 feud / grace / betray / redeem 等 lifeEvent，写入 delta |
| 3. 双向插入 | 向 partyA 与 partyB 的 lifeEvents 各插一条（叙述视角不同） |
| 4. 更新关系状态 | 全局关系表 status 更新（active→broken 等） |
| 5. 涟漪校验 | 检查该关系变更是否触发其他 NPC 的连锁反应（见 §五） |

### 4.3 玩家介入的方式

| 介入方式 | 改变的关系 | 机制 |
|----------|-----------|------|
| 救其师 | 师徒关系 strength +、师对玩家 grace | 师被救后，徒对玩家好感提升 |
| 杀其敌 | 宿敌关系 status→broken、敌对 NPC 退场 | 玩家替 NPC 解决宿敌，NPC 感恩 |
| 离间同门 | 同门关系 strength−、可能转宿敌 | 剧情选择挑拨、散布情报 |
| 成其缘 | 情缘关系 strength +、可能解锁专属剧情 | 玩家撮合或赠信物 |
| 断其缘 | 情缘关系 status→broken、双方 morality 变化 | 玩家干预、拆散、或一方死亡 |

## 五、关系密度基准与涟漪控制

### 5.1 核心NPC关系密度

> 不是每个核心 NPC 都有预设关系——密度过高会让关系网 tangled 不可控。

| NPC 类别 | 数量（基准） | 有预设关系比例 | 平均关系数 |
|----------|--------------|----------------|------------|
| 剧情伙伴 / 主线关键 | ~20 | 80% | 2~3 条 |
| 门派核心（掌门 / 长老 / 精英） | ~80 | 60% | 1~2 条 |
| 功能 NPC（商店 / 铁匠 / 药铺） | ~50 | 20% | 0~1 条 |
| 可招揽弟子（寻访） | ~100 | 30% | 0~1 条 |
| **合计核心 NPC** | **~250** | **~40%** | **平均 1 条** |

> **设计意图**：约 100 个核心 NPC 有预设关系，总关系条目约 150~200 条——足够制造"江湖人际网"的丰富感，又不至于脚本工作量爆炸。

### 5.2 涟漪效应控制

> 一条关系变更可能触发连锁——需控制深度，防"蝴蝶效应"失控。

| 涟漪深度 | 规则 | 示例 |
|-----------|------|------|
| 一级（直接） | 关系双方 lifeEvents 更新 | 杀 A 的师 B，A 插入 revenge 事件 |
| 二级（关联） | 与双方有关系的第三方 NPC 反应 | A 的同门 C 得知，C 对玩家 morality− |
| 三级（停止） | **不再传播**，防连锁失控 | C 的其他关系不受影响 |

> **关键取舍**：涟漪只到二级——保证玩家介入有"看得见的后果"，但不让一个动作牵动半个江湖。三级以上由剧情脚本显式触发，不做自动传播。

## 六、示例关系网（4 伙伴 + 典型NPC）

> 用已标定的 4 个伙伴与几个典型 NPC 演示关系网如何编织。

### 6.1 谢九的关系网

| 关系 | 类型 | 对方 | 强度 | 起源 | 玩家介入钩子 |
|------|------|------|------|------|--------------|
| 师徒（师） | master-disciple | 某 已退场名宿 | 3 | 谢九年轻时拜师 | 谢九好感≥知己解锁「旧事重提」，揭示其师秘境往事 |
| 宿敌 | nemesis | 幽月教某 长老 | 2 | 年轻时卷入秘境事件结仇 | 玩家若与幽月教结盟，谢九关系紧张 |

### 6.2 陆青崖的关系网

| 关系 | 类型 | 对方 | 强度 | 起源 | 玩家介入钩子 |
|------|------|------|------|------|--------------|
| 同门 | fellow | 凌云阁掌门 | 2 | 凌云阁弟子 | 阶段3-4 倒向主角→同门转宿敌（status 变化） |
| 师徒（徒） | master-disciple | 凌云阁某 长老 | 2 | 拜师学剑 | 「青崖明志」后师徒关系 broken，解锁真传 |

### 6.3 月无瑕的关系网

| 关系 | 类型 | 对方 | 强度 | 起源 | 玩家介入钩子 |
|------|------|------|------|------|--------------|
| 同门 | fellow | 幽月教某 师姐 | 2 | 幽月教同门 | 师姐可能与玩家敌对，月无瑕夹在中间 |
| 宿敌 | nemesis | 六扇门某 捕头 | 1 | 暗杀任务结仇 | 玩家若同时结交周铁山，月无瑕关系紧张 |

### 6.4 周铁山的关系网

| 关系 | 类型 | 对方 | 强度 | 起源 | 玩家介入钩子 |
|------|------|------|------|------|--------------|
| 师徒（徒） | master-disciple | 六扇门某 老捕头 | 3 | 师承缉捕刀法 | 老捕头若被凌云阁害，周铁山立场转变（转正催化剂） |
| 宿敌 | nemesis | 月无瑕 | 1 | 缉捕暗杀案 | 玩家若同时招月无瑕与周铁山，需调解二人 |

### 6.5 关系网拓扑示意

> 4 伙伴通过预设关系串联起五大势力——玩家招一个伙伴，就牵出一张关系网。

| 伙伴 | 串联的势力 | 关系链 |
|------|-----------|--------|
| 谢九 | 幽月教（宿敌）+ 已退场名宿（师） | 玩家→谢九→宿敌（幽月教长老） |
| 陆青崖 | 凌云阁（同门/师） | 玩家→陆青崖→凌云阁掌门 + 长老 |
| 月无瑕 | 幽月教（同门）+ 六扇门（宿敌） | 玩家→月无瑕→幽月教师姐 + 六扇门捕头 |
| 周铁山 | 六扇门（师）+ 幽月教（宿敌） | 玩家→周铁山→六扇门老捕头 + 月无瑕 |

> **设计意图**：月无瑕与周铁山互为宿敌——玩家若同时招两人入队，需调解二人关系，这正是"江湖人际网"制造的游戏性与叙事张力。

## 七、关系网的剧情脚本化

### 7.1 关系事件作为剧情钩子

| 钩子类型 | 触发条件 | 剧情用途 |
|----------|----------|----------|
| 师徒线 | 玩家访问某 NPC，其师在场 | 揭示师承、传授功法、师徒 reunion |
| 宿敌线 | 两宿敌 NPC 同区域 | 触发战斗 / 调解 / 选边站 |
| 同门线 | 玩家与某门派友好值变化 | 同门 NPC 态度连锁变化 |
| 情缘线 | 双方好感度达阈值 | 触发专属支线、结局分支 |

### 7.2 脚本化原则

| 原则 | 说明 |
|------|------|
| 显式触发 | 关系事件由剧情脚本 / 奇遇**显式**触发，不自动传播 |
| 双向对称 | 关系触发时双方 lifeEvents 都更新 |
| 可序列化 | 关系状态可存档、可复现 |
| 玩家主体 | 关系变更**必须**由玩家行为或玩家在场的事件驱动 |
