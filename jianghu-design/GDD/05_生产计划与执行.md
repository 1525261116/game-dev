## 5.1 里程碑与排期（基线：精简版 / 5 人 / 22 个月）

| 里程碑 | 时间 | 交付物 | 通过门槛（Gate） |
|--------|------|--------|------------------|
| **M0 立项与技术预研** | 月 0~1.5 | 引擎选型报告、技术预研 Demo、范围基线确认 | ① 引擎锁定 ② 精简版范围签字 ③ 版号路径决策 |
| **M1 原型** | 月 1.5~4 | 可玩战斗循环 + 养成闭环（无美术） | ① 100 场自动模拟战斗通过 ② 伤害公式与参考面板偏差 ≤ 10% ③ 单场战斗 30~90 秒 |
| **M2 垂直切片** | 月 4~8 | 中原·洛阳完整体验（30 分钟） | ① 见 5.2 垂直切片 Gate ② **单条奇遇 ≤ 2.5 人日** ③ 双端真机可跑 |
| **M3 Alpha** | 月 8~14 | 全部系统落地 + 内容 40% | ① 系统功能 100% 完成 ② 存档格式冻结 ③ 三档设备性能达标 |
| **M4 Beta** | 月 14~19 | 内容 80% + 双端包体达标 | ① 主线可完整通关 ② 崩溃率 < 1% ③ 首包满足渠道限制 |
| **M5 上线准备** | 月 19~22 | 本地化、认证、平衡、发行物料 | ① 存档兼容测试通过 ② 商店页与愿望单 ≥ 3 万 ③ 数值终审通过 |
| **M6 PC/Steam 首发** | 月 22 | Steam 全球 + 移动海外 | ① 无 P0 缺陷 ② 首周好评率 ≥ 80% |
| **M7 国内移动上线** | 月 24+（取决于版号） | 国内 iOS/Android 全渠道 | 版号到位后方可商业化收费 |
| **M8 内容扩展** | 上线后每 6 个月 | DLC / 免费更新（东南·泉州、隐藏势力线） | 按销量决定扩展规模 |

**关键路径**：引擎预研 → 战斗与数值原型 → 配置表工具链 → 内容量产 → 双端包体治理 → 版号。
**一级风险路径**：**版号**。必须与研发并行推进，不得作为上线前的最后一步（详见 5.7）。

## 5.2 垂直切片 Gate（M2 硬门槛）

> 未达标不进入量产。这是整个项目最早也最重要的止损点。

| # | 门槛项 | 标准 | 不达标处理 |
|---|--------|------|------------|
| 1 | 可玩时长 | 1 个完整区域可玩 30 分钟 | 延期 1 个月 |
| 2 | **单条奇遇工时** | **≤ 2.5 人日**（从设计到进包） | **立即砍 40% 内容规划** |
| 3 | 数据驱动 | 改一行配置 → 游戏内生效，全程 < 10 分钟 | 补工具链，暂停内容生产 |
| 4 | 双端 | PC + 1 款中低端 Android 真机流畅运行 | 引擎重评估 |
| 5 | 性能 | 中低端 Android 稳定 ≥ 30 FPS，内存 < 800MB | 专项优化 |
| 6 | 存档 | 手机 ↔ PC 存档可互转 | 暂停，重构存档格式 |
| 7 | 战斗平衡 | 四流派两两胜率差 ≤ 15 个百分点 | 调数值 |
| 8 | 团队自持 | 能独立定位并修掉 1 个引擎级问题 | 评估换引擎或补人 |
| 9 | 战前布阵乐趣 | 盲测中 ≥ 70% 玩家认为"布阵影响胜负" | 重做战斗交互 |

**残酷决策点**：用第 2 项的实测值反推全部奇遇所需人月。**对不上就在此砍量，绝不拖到量产期**。

## 5.3 团队配置

### 5.3.1 基线配置（5 人核心 + 外部资源）

| 角色 | 人数 | 职责 | 关键能力要求 |
|------|:----:|------|--------------|
| 制作人 / 主策 | 1 | 范围控制、数值终审、发行对接 | 能砍需求；懂商业化与版号流程 |
| 系统策划 / 数值策划 | 1 | 系统设计、配置表、数值模拟、平衡 | 会写脚本跑模拟；Excel 熟练 |
| 客户端程序 | 2 | 战斗、系统、UI、双端适配、工具链 | 熟悉选定引擎 + 配置表管线 + 热更 |
| 美术（含 TA 职责） | 1 | 美术风格守门、UI 规范、外包管理 | 懂 2.5D 斜视角管线 |

**外部资源**：立绘/场景/特效外包、配乐外包、本地化外包、QA 外包（Beta 期 2~3 人）。
**可选增配（有预算时）**：关卡策划 1（内容量产提速 40%）、音频 1、QA 1。

### 5.3.2 内容生产能力测算

| 项 | 数值 |
|----|------|
| 内容人日需求（精简版） | ≈ 800 人日 |
| 可投入内容的人力 | 1.5 人（主策 0.5 + 系统策划 0.5 + 关卡 0.5） |
| 内容生产周期 | `800 ÷ 1.5 ÷ 21 ≈ 25 个月` |
| **结论** | **必须增配关卡策划 1 人，或扩大外包**；否则内容成为唯一瓶颈 |

> **这是本计划最需要正视的数字**：内容人日需求 ÷ 内容人力 = 项目实际周期。任何"多加系统"的需求都必须先换算成内容人日。

## 5.4 技术预算（对引擎的硬约束）

> 这些数字是**引擎选型的需求输入**，也是验收标准。

| 项 | 目标 | 说明 |
|----|------|------|
| Android 首包 | ≤ 300MB | 其余资源分包下载 |
| Android 全量 | ≤ 2.5GB | 含全部区域 |
| iOS 全量 | ≤ 3GB | App Store 蜂窝下载限制 |
| PC 安装包 | ≤ 12GB | Steam |
| 中低端 Android | ≥ 30 FPS，内存 < 800MB | 4v4 战斗 + 场景 |
| 中端 Android | ≥ 45 FPS | |
| PC 最低 | ≥ 60 FPS（1080p） | |
| 冷启动到主界面 | < 5 秒（中端机） | |
| 场景加载 | < 3 秒（SSD）/ < 6 秒（移动） | |
| 单场战斗逻辑耗时 | < 50ms（4v4，30 回合） | 支持"预结算 + 表现分离" |
| 存档大小 | ≤ 2MB | 版本化 + 可迁移 |
| 配置表全量加载 | < 200ms | 二进制/压缩 JSON |

**架构强制要求**

1. **预结算 + 表现分离**：战斗结果先算完，再播动画。确保低端机也能跑，且战斗逻辑可脱离渲染做自动化测试。
2. **输入抽象层**：触屏 / 键鼠 / 手柄三模式从第一天就抽象，不允许 UI 直接读具体输入。
3. **数据契约**：所有内容经配置表驱动（见 4.7.2），代码不含硬编码内容。
4. **存档版本化**：JSON + 校验字段 + 迁移函数；不使用引擎对象序列化直接落盘。
5. **确定性战斗**：同种子同结果（跨端一致），便于回放与测试。

## 5.5 预算与回本测算

> 所有金额为**经验区间估算**，非报价。人均综合成本按 2 万/月计（含社保、设备、办公分摊）。

### 5.5.1 三档预算方案

| 项 | 低配（3 人 / 22 月） | **中性（5 人 / 22 月）** | 高配（8 人 / 24 月） |
|----|---------------------|--------------------------|----------------------|
| 人力工资 | 132 万 | **220 万** | 384 万 |
| 美术外包 | 40 万 | **70 万** | 140 万 |
| 音频 | 5 万 | **12 万** | 30 万 |
| 本地化 | 3 万 | **8 万** | 20 万 |
| 引擎授权 | 0（门槛内） | **0~15 万** | 0~30 万 |
| 第三方插件/工具 | 2 万 | **8 万** | 15 万 |
| 发行/认证/版号/设备/服务器 | 13 万 | **30~80 万** | 80 万 |
| **总计** | **≈ 195 万** | **≈ 350~410 万** | **≈ 670~900 万** |

### 5.5.2 回本测算（中性方案，取 380 万）

| 渠道 | 单价 | 平台分成后净收入 | 回本所需量 |
|------|------|------------------|-----------|
| PC（Steam，¥68 买断） | ¥68 | ≈ ¥42（30% 分成 + 税） | **≈ 9.0 万份** |
| 移动（通行证 ¥35） | ¥35 | ≈ ¥21（30% 分成） | 需 18 万份解锁（按 6% 转化 = 300 万下载） |
| 组合（PC 7 万 + 移动 8 万份解锁） | — | 294 万 + 168 万 = 462 万 | **首年可回本** ✓ |

**对标参考（🟡 二手来源）**

- 《我的侠客》PC 端上线 WeGame 与蒸汽平台，**定价 69 元**（[IT之家](https://www.ithome.com/0/662/318.htm)）——与本作 PC 定价 ¥68 定位一致，说明国区武侠 RPG 的买断价格锚点已验证。
- 《我的侠客》媒体称"**5 个人做的武侠手游**"，公测即登顶苹果排行榜——小团队做武侠 RPG 的可行性证据。
- 《烟雨江湖》已有 Steam 商店页与试玩版——同品类移动端产品向 PC 迁移的路径成立。

**结论**：中性方案在 **PC 7 万份 + 移动 8 万份解锁** 的组合下首年可回本。若只有 3 万份 PC 销量，则无法回本 —— **因此宣发与愿望单积累必须与研发并行（M3 起开始铺量）**。

### 5.5.3 收入结构目标（首年）

| 来源 | 占比 | 说明 |
|------|:----:|------|

## 5.6 研发流程与工具链

### 5.6.1 迭代节奏

| 节奏 | 内容 |
|------|------|
| 每日 | 自动构建（三档设备）+ 配置表校验 + 单元测试 |
| 每周 | 可玩版本（Weekly Build）+ 数值变更评审 |
| 双周 | 内容评审会（新内容过 4.9 验收标准） |
| 每月 | 里程碑复盘 + 范围再确认（砍需求优先于延期） |

### 5.6.2 必须交付的内部工具

| 工具 | 用途 | 优先级 |
|------|------|:------:|
| 配置表导出器 | Excel/CSV → 运行时数据 + 校验 | P0 |
| 配置表校验器 | 引用完整性、概率和、数值边界、单调性 | P0 |
| 战斗模拟器 | 批量跑战斗，输出 TTK/胜率/流派分布 | P0 |
| 事件节点编辑器 | 策划可视化配置奇遇/任务分支 | P0 |
| 数值面板预览器 | 改数值即时看 L2 变化 | P1 |
| 掉落模拟器 | 1000 次模拟校验掉率 | P1 |
| 存档迁移测试器 | 老版本存档 → 新版本 | P1 |
| 热更演练脚本 | 不发版修数据的完整流程 | P1 |
| 本地化导出/导入 | 文本 ID ↔ 翻译表 | P1 |
| 性能回归看板 | 每版本三档设备帧率/内存曲线 | P2 |

> **原则**：工具链的投入必须在内容量产**之前**完成。工具晚一个月，内容就慢三个月。

### 5.6.3 版本控制与分支

| 分支 | 用途 | 规则 |
|------|------|------|
| `main` | 可发布版本 | 只接受通过全部 Gate 的合并 |
| `develop` | 日常集成 | 每日构建 |
| `feature/*` | 功能开发 | 生命周期 ≤ 2 周 |
| `release/*` | 上线候选 | 冻结内容，只修 bug |
| `content/*` | 内容批量生产 | 配置表为主，可与程序解耦合并 |

**约定**：美术资源使用 Git LFS 或独立资源库；配置表变更必须有策划签名。

## 5.7 合规与风险登记册

### 5.7.1 内容合规（研发期就必须规避）

| 风险项 | 对策 |
|--------|------|
| 血腥/暴力表现 | 战斗采用水墨化表现，不做断肢/血液喷溅；受伤用"墨点扩散" |
| 历史人物与朝代 | 使用架空王朝（不直接使用真实朝代名与历史人物） |
| 穿越题材表述 | 避免"改变历史"类表述；穿越仅作为叙事装置 |
| 宗教与民俗 | 寺庙/道观场景做架空处理，不指涉真实宗教组织 |
| 未成年人保护 | 无抽卡付费、无广告、无社交；实名与时长限制按平台要求接入 |
| 酒类表现 | 酿酒系统做"江湖酒文化"表述，不做饮酒鼓励 |
| 赌博相关 | 寻访为游戏内掉落道具消耗，**不涉及真实货币**，界面公示概率 |
| 版号申报材料 | 软著、内容说明、脚本全文、演示视频 —— 项目中期即开始准备 |
| 隐私合规 | 最小化收集；无账号也能完整游玩（云存档为可选项） |
