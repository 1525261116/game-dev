# 生图提示语 · 角色部件 v1.0

> 用途：用豆包 AI 生成《江湖从心》的可换装角色部件贴图（cutout 骨骼 / 方案 C）
> 配套：`docs/asset-pipeline.md`（管线手册）、`docs/rig-spec.md`（骨架规范）、`jianghu-game/templates/skin/`（对位模板）
> 可复制纯文本版：`生图提示语_角色部件_v1.0.txt`

---

## 0. 一句话流程

**先生成一张全身立绘当"风格锚点" → 逐部件生图（把立绘当参考图）→ 抠底 + 自动对位 → 校验 → 刷新。**

| 步 | 做什么 | 用什么 |
|:--:|--------|--------|
| 0 | 生成**全身立绘**（一次）作为风格/比例/配色的锚点 | 豆包 · 提示语见 §2 |
| 1 | 逐部件生成（**把立绘作为参考图**，保证同一套衣服的配色一致） | 豆包 · 提示语见 §4 |
| 2 | 抠底 + 裁边 + 缩放到精确画布 + **自动对位关节** | `node tools/fit-skin-part.ts <图或目录> --slot=<slot> --body=<体型>` |
| 3 | 校验并生成 `skin.json` | `pnpm skin:gen` |
| 4 | 浏览器刷新看效果 | Vite 热更新，不用重启 |

> **好消息**：**不用一次画全 17 个部件**。在 `skin.json` 里声明 `art`（底图角色），
> 没画的部件会**自动继承底图** —— 所以"先画躯干 + 头 + 左右上臂 + 左右前臂 6 张"就能试穿。
> `pnpm skin:gen` 会明确告诉你"自有 6 张，其余 11 个部件继承底图"。

## 1. 生图前必须知道的 5 条硬约束

这 5 条不是审美偏好，而是**骨架要求**，违反任何一条都会在导入期报错或一摆动作就穿模。

| # | 约束 | 为什么 |
|:-:|------|--------|
| 1 | **统一朝向：面向画面右侧的 3/4 侧视** | 朝左由程序水平镜像，**省一半贴图**。混朝向会导致镜像后动作反向 |
| 2 | **一次只画一个部件**，画面里不要出现其他身体部位 | 关节位置靠"内容包围盒"自动推断；多画一条腿就会把包围盒撑坏 |
| 3 | **纯色背景**（纯白 `#ffffff` 最好）、无阴影、无地面、无光晕 | 工具按背景色抠底；渐变背景/投影会留下脏边 |
| 4 | **部件要"完整但不多余"**：上臂就是上臂，不要带手掌 | 尺寸按骨架盒等比缩放，多出来的部分会被压进盒子里 |
| 5 | 边缘干净、**关节那一端朝向明确**（躯干的底边=腰、上臂的顶边=肩） | 关节必须落在画布枢轴位置（见 §3 表） |

> ❌ 反例：让 AI 画"一个古代侠客"→ 它给你一个全身像 + 背景 + 影子。
> ✅ 正例：让 AI 画"一件深青色交领右衽战袍的上半身（不含头、不含手臂），正面偏右 3/4 视角，纯白背景"。

## 2. 第 0 步：全身立绘（风格锚点）

先出一张全身立绘，后面逐部件生成时把它当**参考图**（豆包支持参考图/图生图），这样衣料、纹样、配色、笔触能保持一致。

**提示语（中文，直接粘贴）：**

中国古代武侠角色全身立绘，成年男性，身高约 7.5 头身，站姿自然、双臂微张便于后续拆件；身着深青色交领右衽长袍，腰间布带，下着深灰长裤，黑色软靴；面向画面右侧 3/4 侧视；水墨武侠风格，工笔与写意结合，墨线勾边，局部淡彩；纯白背景，无影子、无地面、无文字、无水印、无边框；构图居中，全身完整不裁切

| 触发点 | 说明 |
|--------|------|
| 7.5 头身 | 我们的骨架是"正常比例剪纸小人"（成年男 148px），不要 Q 版 |
| 双臂微张 | 手臂与躯干留缝，方便你目测关节位置 |
| 面向右 3/4 | 与骨架铁律一致 |
| 纯白背景 | 后面要抠底 |

## 4. 逐部件提示语（可直接粘贴）

### 4.1 通用模板

**结构**：`[部件是什么] + [朝向/视角] + [风格] + [背景与排除项]`

| 段 | 内容 |
|----|------|
| 部件 | 见下表（**一次只写一个部件**） |
| 视角 | 面向画面右侧 3/4 侧视 |
| 风格 | 水墨武侠、墨线勾边、平涂淡彩、皮影剪纸质感 |
| 背景 | 纯白背景、无阴影、无地面、无文字、无水印、无边框 |

## 4.4 ⚠️ 第二轮修订（v2）—— 首轮试穿暴露的三个坑

首轮用本文件 §4.2 的提示语生成了 6 件（躯干 / 头 / 左右上臂 / 左右前臂），
风格与质量都达标，但**挂到骨骼上**暴露了三个问题。它们都不是"画得不好"，而是"画得不符合部件规范"：

| # | 现象 | 根因 | v2 提示语怎么改 |
|:-:|------|------|-----------------|
| 1 | 袖子与躯干**交叉成 X** | 模型按"手臂自然下垂"画成了斜置，而部件必须像**平铺在桌面上** | 加「**竖直摆放、笔直向下、左右边缘平行、不是弯曲手臂**」 |
| 2 | 头**偏小**、脸只占画布 60% 宽 | 发带飘带也被算进内容包围盒，把脸挤小了 | 加「**不要画发带、不要飘带、不要长发飘散**」 |
| 3 | 躯干下摆**压到骨盆** | 画到了腰带以下，多出的衣摆被挤进躯干骨骼盒 | 改为「**从领口到腰带为止，腰带以下不要画**」 |

另外两条全局修订（写进 `stylePrefix` / `styleSuffix`）：

| 修订 | 原因 |
|------|------|
| 加「物品像**平铺在桌面上**一样摆放，主轴垂直或水平、不要透视倾斜」 | 这是整套 cutout 管线的根本前提：部件是"零件"，不是"插画" |
| 加「单件居中、**四周留白**」 | 贴边裁切会让内容包围盒失真 |

> 已落地的机器可读版本在 `jianghu-game/data/art-prompts.json`（含 16 个部件的完整提示语 + `_notes` 修订依据），
> 用 `pnpm art:gen --dry` 可以直接看到最终拼接结果。

### 4.5 第三轮发现（v3：补齐 16 件后）

v2 把「手臂斜置」修好了。补齐 16 件并挂到骨骼上后，又暴露 4 个新问题（已记入 `art-prompts.json` 的 `_notes` 第 8~11 条）：

| # | 现象 | 下一版对策 |
|:-:|------|-----------|
| 8 | **躯干又长出了袖子** → 与上臂部件叠加成"双层袖" | 提示语加「无袖，肩部是袖根切口（armhole），不要画袖子」 |
| 9 | **左右同部件色调不一致**（左小腿被画成近黑） | 改为「与近侧完全同色」，远近层次交给引擎侧处理 |
| 10 | **腰部露白**（torso 到腰带 + pelvis 只有 68×32，接缝露出背景） | torso 保留一点腰下布料，或让 pelvis 内容铺满画布 |
| 11 | 上臂 / 前臂**各带袖口束带** → 手臂出现 2~3 道横带 | 束带只放在前臂末端 |

两条 **v3 关键修复**（都已落进工具与配置）：

| 修复 | 说明 |
|------|------|
| **画布比例决定部件朝向** | 给竖构图（`1024x2048`）模型才把袖子画成竖的；给横构图它画成横的（实测 `upperArmL` 内容盒 2009×1408 = 横袖子）。四肢统一竖构图、脚横构图（`2048x1024`），写进 `art-prompts.json` 的 `sizes` 字段 |
| **四肢对位用 `fill`（非等比铺满骨骼盒）** | AI 画的袖子宽高比常与骨骼盒差很远，等比缩放后只剩几像素宽 ≈ 手臂消失。四肢是"软性筒状物"，**骨架盒本就是它的形状权威**；头/躯干/手/脚/披风/武器仍用 `contain`，避免脸被拉变形 |

## 5. 第 2 步：抠底 + 自动对位（**这一步把 AI 图变成能用的贴图**）

AI 出图尺寸是随机的（512×768、1024×1024…），骨架却要求**精确画布 + 关节在枢轴**。
一步搞定：

| 场景 | 命令 |
|------|------|
| 单张 | `node tools/fit-skin-part.ts 原始图.png --slot=torso --body=male_adult --out=输出路径/torso.png` |
| **批量（推荐）** | 把原始图命名成 `<slot>.png` 放进一个目录，然后 `node tools/fit-skin-part.ts 原始目录/ --char=ren_dao --body=male_adult` |
| 先看效果不写盘 | 加 `--dry` |

它会依次做四件事，并打印一张报告：

| 步 | 做什么 | 报告里对应字段 |
|:--:|--------|----------------|
| ① | **抠底**：把纯色背景变透明（带软过渡，不留白边） | `抠底：是（#ffffff，tol=36）` |
| ② | **裁边**：去掉四周空白，得到内容包围盒 | `内容 127×289 @206,207` |
| ③ | **等比缩放**到画布（`contain` 默认不拉伸） | `缩放 0.318× → 输出 80×92` |
| ④ | **对枢轴**：把内容盒上的关节钉到画布枢轴 | `枢轴 0.5,1 → 画布 (40, 92) 已钉住` |

常用参数：

| 参数 | 说明 |
|------|------|
| `--key=auto`（默认）／`--key=none`／`--key=#ffffff` | 抠底方式。背景复杂时先用你手上的**抠图工具**去底，再用 `--key=none` |
| `--key-tol=36` | 容差，留白边就调大、抠掉了主体就调小 |
| `--fit=contain`（默认）／`height`／`width` | 贴合方式。`contain` 最安全；`height` 适合手臂/腿这类"长条" |

> **对不准怎么办？** 手动对齐用 `jianghu-game/templates/skin/<体型>/<slot>.png`：
> 那是 4× 放大的模板，**粉色十字交点就是关节必须落的位置**（文件里标注了真实尺寸）。
> 把模板垫在底层 → 让关节压住十字 → 缩到 1/4 导出。

## 6. 武器贴图（可先跳过，用占位）

武器**按「类型 × 品质」共享**（全角色共用，是外观付费的切入点），不随角色走。

| 项 | 值 |
|----|-----|
| 路径 | `jianghu-game/assets/weapons/<组>/<组>_<后缀>.png` |
| 组 | `dao` 刀 ／ `jian` 剑 ／ `qiang` 枪 ／ `anqi` 暗器 ／ `qimen` 奇门 |
| 品质后缀 | 凡 `fan` ／ 良 `li` ／ 上 `bao` ／ 极 `shen` ／ 绝 `chuan` |
| 画布 | **14×112**（@2×，枢轴 0.5, 0.12 = 握把在顶部下 12%） |

**提示语要点**：`"一把中国古代<刀/剑/长枪/暗器/奇门兵器>，竖直放置、刃朝上、握把在下 1/8 处，<品质形容>，水墨武侠风格墨线勾边，纯白背景，只有武器、无人物、无手、无文字"`

品质形容词建议：凡品"朴素无纹"／良品"素面钢质"／上品"有简单缠柄与纹样"／极品"暗金色纹饰、镶玉"／绝世"鎏金繁复纹饰、宝石镶嵌、刀身有流光"。

## 7. 第 3 步：校验与生效

| 命令 | 作用 |
|------|------|
| `pnpm skin:gen` | 扫描 → 校验 → 生成 `skin.json`（**有 error 不写盘**） |
| `pnpm skin:check` | 只校验（CI） |
| `pnpm skin:templates` | 重新生成对位模板（`--force`） |
| 刷新浏览器 | Vite 热更新，不用重启 dev server |

出错的三种典型长相（改完再跑一次即可）：

| 报错 | 含义 |
|------|------|
| `[BAD_SIZE] 「torso」画布应为 80×92，实际 90×103` | 没用 `fit-skin-part.ts` 对位，或直接拖了原图进目录 |
| `[BAD_PIVOT] 「footR」枢轴应为 0.25,0.5` | 手工裁切时关节没落在枢轴位置 |
| `[MISSING_PART] 缺少必需部件「thighL」` | 该角色**没有声明 `art` 底图**，必须 17 件齐全；声明 `art` 后未画部件会自动继承底图 |

## 8. 试穿阶段的推荐姿势（第一版）

| 步 | 动作 |
|:--:|------|
| 1 | 跑 `pnpm art:placeholder` 先有一套占位图（已有则可跳过） |
| 2 | 新建角色目录 `assets/chars/<你的角色id>/`，写一份 `skin.json`：`{ "id": "...", "name": "...", "body": "male_adult", "art": "base_male", "palette": {}, "parts": {} }` |
| 3 | 豆包生成**躯干 / 头 / 左右上臂 / 左右前臂 6 张** |
| 4 | `node tools/fit-skin-part.ts 原始目录/ --char=<角色id> --body=male_adult` |
| 5 | `pnpm skin:gen` —— 会提示"自有 6 张，其余 11 个部件继承底图" |
| 6 | 刷新浏览器：你的 6 张已经穿在身上，其余仍是占位图 |
| 7 | 觉得关节不对 → 回报"哪个 slot 的关节偏了、往哪个方向偏多少"，我改 `fit` 参数或帮你调模板 |

> 这一步的意义是**先验证"你的美术 + 我们的骨架"能不能合上**，
> 花 30 分钟就能回答，不用等 17 张全画完。
