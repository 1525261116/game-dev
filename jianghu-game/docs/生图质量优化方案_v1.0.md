# 生图质量优化方案 v1.0

> 触发：首轮 `hero_trial`（16 件 AI 贴图）效果不理想，且"在豆包上用同一模型质量好得多"
> 分析日期：2026-10-12｜分析方式：**同模型对照实验 + API 参数探测 + 游戏内像素测量**
> 结论一句话：**原画质量不是主要瓶颈 —— 真正的杀手是「游戏里把 1024×2048 压进 12×26 像素」，其次是「提示语写成了约束清单」。**

---

## 0. 一页纸结论

| # | 结论 | 证据 | 优先级 |
|:-:|------|------|:------:|
| 1 | **游戏侧尺寸是天花板**：上肢绘制盒只有 12×26 逻辑像素，一张 1024×2048 的原画要丢掉 **99.9%** 的细节 | 逻辑 960×540，角色 148px×0.52 = **77px 高（占画面 14%）**；参考视频角色占 **35%** | 🔴 P0 |
| 2 | **提示语写法是最大可控变量**：把"约束清单"换成"正向美术描述"，织物纹理 / 褶皱体积 / 飞白笔触立刻出现 | 同模型、同尺寸、同部件，只改提示语：见 `preview/ai-art/09-prompt-quality-gap.png` | 🔴 P0 |
| 3 | **尺寸 = 细节预算**：API 的 `usage.output_tokens` 与像素数成正比（2048² = 16384，1024×2048 = 8192）；面积上限 4,624,220 px | 探测：`4096x4096` 被拒（"image area must be at most 4624220 pixels"） | 🟠 P1 |
| 4 | **参考图（i2i）可用**：`image` 入参接受 **URL 或 base64 data URI**，且能同时提升质量与一致性、还消掉了抠不干净的背景墨点 | 探测：`input_images=1` 成功；对比图右栏 | 🟠 P1 |
| 5 | **`guidance_scale` 不被该模型支持**（HTTP 400），`size` 预设只认 `1K`/`2K`（`4K` 报错），`seed` 可用 | 三次参数探测 | ⚪ 知悉 |
| 6 | 游戏侧另有 4 个**规则性**缺陷（双层袖/露白/横带/左右色差），与模型无关 | 16 件挂到骨骼后实测 | 🟡 P2 |

## 1. 分析：为什么"豆包上看着好，我们这里差"

### 1.1 差距的真实来源（按影响排序）

| 排名 | 来源 | 说明 | 量化 |
|:----:|------|------|------|
| 1 | **显示尺寸太小** | 我们的角色只有 77px 高，胳膊 12×26px。原画再精美，缩到 12px 宽就只剩几个色块 | 原画 1024×2048 → 目标 24×52 → **细节保留率 0.1%** |
| 2 | **提示语"约束清单"化** | 我的提示语约 40% 文字在写"不含手掌、不含小臂、无阴影、无地面、无人物、无水印、无边框、不要出现完整人体…"。模型把注意力分给了这些否定项，正向的"画成什么样"反而很单薄 | 见 §1.2 对照实验 |
| 3 | **任务性质不同** | 豆包上是"画一张插画"（有场景、有光、有叙事）；我们是"孤立部件产品图"。同一模型做产品图天然不如做插画 | 参考视频里的角色是**完整插画式演出**，不是抠件拼装 |
| 4 | **细节预算被砍半** | 我给四肢用了 `1024x2048`（2.1M 像素），而模型上限是 4.6M 像素。token 预算直接砍半 | `output_tokens` 16384 vs 8192 |
| 5 | 输出格式 | API 只给 **JPEG**（虽有 24h 有效 URL），我们转 PNG 后仍有 JPEG 压缩痕迹 | `output_format: "jpeg"` |

### 1.2 对照实验（关键证据）

![提示语质量差距](preview/ai-art/09-prompt-quality-gap.png)

同一模型 `doubao-seedream-5-0-pro-260628`、同一部件 `upperArmR`、同一尺寸级别，**只改提示语**：

| 栏 | 提示语风格 | 结果 |
|:--:|-----------|------|
| 左 | **v3 旧**：`深青色衣袖的右上臂一段，竖直摆放…不含手掌、不含小臂、不含躯干…无阴影、无地面、无人物、无手…` | 外形偏"灯笼袖/护臂"，两端出现金圈，读起来不像肩袖 |
| 中 | **正向美术描述**：`…布料厚实、可见细密织物纹理与自然褶皱，袖口以浅褐色丝线收边；墨线勾勒轮廓，边缘带飞白笔触，内部以淡墨层层罩染出体积感与明暗关系；工笔与写意结合，博物馆藏品级质感…` | **织物纹理、体积感、褶皱、飞白**全部出现 |
| 右 | 中栏 + **参考图 i2i** | 更干净（背景墨点飞溅消失）、织纹更实、轮廓更利落 |

> 结论：**提示语不是"越严格越好"，而是"越具体、越有画面感越好"**。
> 约束应该只留必要的 2~3 条（纯白背景 / 单件居中 / 无文字），其余交给"画成什么样"。

### 1.3 参数探测结果（全部实测）

| 参数 | 结果 | 备注 |
|------|------|------|
| `size: "4K"` | ❌ 400 InvalidParameter | 预设只认 `1K` / `2K`；其余必须写 `WxH` |
| `size: "4096x4096"` | ❌ 400：`image area must be at most 4624220 pixels` | **硬上限 462 万像素**；`2048×2048`（419 万）已接近 |
| `guidance_scale` | ❌ 400：not supported | 该模型不支持 CFG 调节 |
| `seed` | ✅ 200 | 可用于复现 |
| `image`（参考图） | ✅ 200，`input_images=1` | **URL 与 base64 data URI 都接受** |
| `usage.output_tokens` | `2048²=16384` / `1024×2048=8192` | **= 像素数 ÷ 256**，即"细节预算" |
| 输出格式 | 始终 `jpeg` | 需自己转 PNG |
| 服务端改写提示语 | 无 `revised_prompt` 字段 | 豆包 App 的"聪明"不在 API 侧 —— 所以**差距来自我们的提示语与参数**，不是模型 |

## 2. 优化方案

### P0-1　提示语工程改造（0 成本，立刻见效）

| 改造 | 旧 | 新 |
|------|-----|-----|
| **结构** | 约束清单为主 | **媒介 + 部件正向描述 + 渲染要求 + 极简约束** 四段式 |
| **正向词汇** | 几乎没有 | 细密织物纹理 / 自然褶皱 / 淡墨层层罩染 / 体积感与明暗关系 / 飞白笔触 / 提花纹样 / 缝线与磨亮高光 |
| **品质锚点** | 无 | 「工笔与写意结合、博物馆藏品级质感」 |
| **排除项** | 8~10 条长列表 | 压到 3 条：纯白背景、单件居中、无人物无文字 |
| **比例与朝向** | 用"不含 XX"暗示 | 用**画布尺寸**控制（见 P0-2）——参数比文字可靠 |

已落地：`jianghu-game/data/art-prompts.json`（v4，16 件全部重写，`_notes` 第 12~15 条记录依据）。

### P0-2　尺寸拉满（细节预算翻倍）

| 部件 | 旧 | 新 | 理由 |
|------|-----|-----|------|
| 躯干/头/骨盆/手/披风 | `2K`（实际 2048²） | **`2048x2048`**（419 万像素） | 接近面积上限 |
| 四肢（上臂/前臂/大腿/小腿/武器） | `1024x2048`（210 万） | **`1440x2880`**（415 万） | 竖构图（保证画成竖的）**且**接近满预算 |
| 脚 | `2048x1024`（210 万） | **`2880x1440`**（415 万） | 横构图 + 满预算 |

> 生成时用大尺寸、**由我们自己缩到目标画布** —— 缩放不会增加细节，但生成时省下的细节是永久损失。

### P0-3　游戏侧分辨率与角色尺寸（**画质天花板，最关键**）

| 项 | 现在 | 目标 | 影响 |
|----|------|------|------|
| 逻辑分辨率 | **960×540** | **1280×720**（或 1920×1080） | 同样 77px 的角色，像素量翻倍 |
| 战斗角色缩放 | 0.52 | **0.80 ~ 1.00** | 角色高度 77px → **118~148px** |
| 三行站位 | 行距 128px | 行距 170~200px（配合放大） | 3 行 × 148px = 444px，1280×720 下刚好 |
| 贴图倍率 `ART_SCALE` | 2 | **3** | 贴图画布 24×52 → 36×78，配合屏幕放大仍有富余 |

**量化对比**：

| | 角色占画面高 | 胳膊绘制盒 | 胳膊屏幕像素（1500px 窗口） |
|---|---|---|---|
| 现在 960×540 + 0.52 | 14% | 12×26 | ~19×41 |
| 改后 1280×720 + 0.9 | **31%** | 21×47 | ~46×103 |

**这一条不解决，前面两条的收益会被"压成像素点"吃掉大半。** 参考视频的角色占画面 35%，我们只有 14% —— 差距首先在这里。

### P1-1　参考图（i2i）流程

`image` 入参已接通（`--ref=<文件或URL>`），两种用法：

| 用法 | 命令 | 适用 |
|------|------|------|
| **二轮精修**（推荐先做） | `pnpm art:gen --ref=assets/chars/<id>/raw/v4/upperArmR.png --only=upperArmR --force --out=.../raw/v5` | 已有可接受的部件，要提质量/去背景飞溅 |
| **全角色风格统一** | 先出全身立绘 → `pnpm art:gen --ref=<立绘>` 生成全部部件 | 让 16 件共用同一套衣料与色调 |

> 实测二轮精修效果最好：同一部件做参考时，模型会保持造型、只提升材质与干净度。

### P1-2　抠图健壮性（背景飞溅）

正向美术描述会让模型偶尔加"背景墨点飞溅"（好看但会撑坏内容包围盒）。两种对策：

| 对策 | 说明 |
|------|------|
| ✅ 优先用参考图 | 实测 i2i 输出几乎没有飞溅 |
| 兜底：`keep-largest-component` | 在 `fit-skin-part` 里加一步"只保留最大连通域"，把离散飞溅剔除（约 40 行，纯像素运算） |

### P2　四个规则性缺陷（与模型无关，靠提示语微调 + 引擎兜）

| # | 现象 | 对策 |
|:-:|------|------|
| 8 | 躯干长出袖子 → 双层袖 | 提示语已加「无袖、肩部为袖根切口」，v4 待验证 |
| 9 | 左右同部件色调不一致 | 已改为「远侧手臂」不写"更深一档"；**远近层次交给引擎侧调色**（`palette` 只有 ±10% 明度差） |
| 10 | 腰部露白 | torso 保留腰带下一点布料；或把 pelvis 内容铺满（画布不变） |
| 11 | 手臂 2~3 道横带 | 束带只放前臂末端（v4 已改） |

## 3. 执行顺序（建议）

| 步 | 动作 | 成本 | 预期收益 |
|:--:|------|------|----------|
| 1 | **P0-1 + P0-2 重生成 16 件**（v4 提示语 + 尺寸拉满） | ~18 分钟、16 张 | 原画质量明显提升（织物/体积/干净度） |
| 2 | 按需 **P1-1 二轮精修**问题件 | 每件 ~50 秒 | 收敛到可用 |
| 3 | **正式接入 + 在真机上按 P0-3 改分辨率/角色尺寸** | 代码约 1~2 天 | **真正让画面"看起来是 AI 原画"**（否则一直是像素点） |
| 4 | P1-2 抠图健壮性 / P2 剩余缺陷 | 各 ~0.5 天 | 稳定性 |

> **关键提醒**：第 1 步单独做，你会觉得"原画好了，但游戏里还是糊"——因为瓶颈在第 3 步。
> 两步一起做，画质才会出现台阶式跃升。

## 6. v4 抽样验证结果（2026-10-12 实测）

![v4 抽样验证](preview/ai-art/11-v4-samples.png)

先出 3 张（torso / head / upperArmR）验证方向，结论：**方向正确，头部需一处修正（已修为 v4.1）**。

| 部件 | v3（旧） | v4（正向描述 + 满预算） | 判定 |
|------|----------|------------------------|:----:|
| `torso` | 和服式宽袖、平涂；**袖子是多余的** | **无袖战袍**（"肩部袖根切口"生效）、交领右衽、褐色皮质宽腰带 + 金属扣、开衩下摆与装饰带、**布料体积感与织纹** | ✅ **大胜** |
| `head` | 彩色、但灰调偏平 | ❌ **退步**：被"水墨"带成灰白素描、**丢了肤色**；"素色发带"被理解成**包一条大白布巾**；还画进了肩膀与衣领 | ❌ → v4.1 |
| `head`（v4.1） | — | **肤色自然偏暖、面颊唇色有血色、眼白瞳孔分明**；发簪高髻（无头巾）；发丝浓墨分缕带飞白 | ✅ **最佳** |
| `upperArmR` | 灯笼袖、两端金圈、不像肩袖 | **正确的竖直袖筒 + 下缘袖口 + 褶皱体积 + 布纹**；墨边略重、肩口不够明确 | ✅ **胜** |

### 结论与下一步

| 项 | 结论 |
|----|------|
| v4 提示语方向 | **成立**：正向美术描述 + 尺寸拉满 → 材质/体积/干净度全面提升 |
| 「水墨」风格词的副作用 | 会把**人物类**部件（头/手/肤色）带成灰白素描 → 人物部件要显式写「肤色自然偏暖、有血色、眼白瞳孔分明」 |
| 「发带」类词的风险 | 模型会具象成"包头布巾" → 人物头部**不写发带**，写「发簪固定」 |
| 剩余微调 | 袖子肩口可再明确一句「上端为平直的肩根切口、可见布料横截面」；墨边偏重可把「飞白笔触」改成「利落的细墨线」 |
| **下一步** | ① 全量重生成 16 件（v4 + v4.1，约 18 分钟）→ ② 按 §2 P0-3 改游戏侧分辨率与角色尺寸（**这一步才是画质天花板**） |
