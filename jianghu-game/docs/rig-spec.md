# 骨架与部件规范（rig-spec）

> 版本：v1.0｜适用：方案 C（自研轻量 cutout 骨骼）
> 铁律：**统一 slot 拓扑，新增角色只允许新增贴图，不允许新增 slot。**

---

## 1. 为什么这条铁律不能破

换肤体系依赖"所有角色挂到同一副骨架"。一旦某个角色新增了 slot，
① 动作数据不再通用 ② 校验器会拦住 ③ 换肤回退到逐角色特判，资产量立刻反弹回 N×M。

`src/core/anim/validate.ts` 会在加载时强制检查：**未注册 slot = 报错**。

## 3. 体型预设（3 套，不是每角色一套）

| 体型 | 缩放 | 肩宽系数 | 胯宽系数 | 四肢系数 | 躯干系数 | 实测身高 |
|------|:----:|:--------:|:--------:|:--------:|:--------:|:--------:|
| `male_adult` | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 | **148 px** |
| `female_adult` | 0.94 | 0.86 | 1.06 | 0.98 | 0.96 | **139 px** |
| `burly`（魁梧/BOSS） | 1.12 | 1.28 | 1.12 | 1.02 | 1.12 | **166 px** |

> 目标区间 **140~170 px**（已确认采用「正常比例剪纸小人」）。
> 新增角色时**只选体型 + 换贴图**，不改骨长。

## 4. 作画规范（你按这个画，脚本按这个收）

| # | 规则 | 原因 |
|:-:|------|------|
| 1 | **统一朝向：面向右 3/4 斜视角** | 朝左用程序水平镜像，**省一半贴图** |
| 2 | **枢轴必须在关节旋转中心** | 枢轴错位 → 一摆就穿模，且后期无法修 |
| 3 | 部件之间**重叠 8~12 px** | 旋转时露缝 |
| 4 | 边缘加 **4~6 px 半透明墨迹虚边** | 强化水墨感 + 遮缝（一举两得） |
| 5 | 透明背景 PNG，**不裁边**（保留画布尺寸） | 保证枢轴一致 |
| 6 | 文件命名**严格等于 slot 名** | `tools/gen-skin.ts` 自动生成 `skin.json` |
| 7 | 每角色一张 `palette.json` | 精英怪/弟子复用同一套图、只换色 |
| 8 | 立绘与战斗部件**分开两组资产** | 战斗用小尺寸，剧情用大立绘 |
| 9 | 先过**剪影评审**再细化 | 剪影决定辨识度，改剪影便宜 10 倍 |

### 画布尺寸（按 2× 设计，游戏内缩放 0.5）

| slot | 画布 @2× | 枢轴位置 |
|------|:--------:|----------|
| `pelvis` | 68×32 | 中心 |
| `torso` | 80×92 | 底部中心 |
| `head` | 48×51 | 底部中心 |
| `upperArmR/L` | 24×52 | 顶部中心 |
| `forearmR/L` | 22×48 | 顶部中心 |
| `handR/L` | 20×20 | 顶部中心 |
| `thighR/L` | 28×64 | 顶部中心 |
| `shinR/L` | 24×60 | 顶部中心 |
| `footR/L` | 36×16 | 距左端 25% 处、垂直居中 |
| `weapon`（刀/剑） | 14×112 | 距顶部 12% 处 |
| `cloak`（可选） | 92×116 | 距顶部 5% 处、水平居中 |

> 上表是 **`male_adult` 体型**的尺寸；`female_adult` / `burly` 的躯干/骨盆/披风会按躯干系数缩放，

> `head` 为 48×**51** 而不是 52：骨架里头部乘了 0.98（"头略小一点"，见 `src/data/rigs.ts`）。
> 唯一权威是代码：跑 `node tools/gen-skin.ts --check`，尺寸不对会直接告诉你应该是多少。

## 6. 动作数据格式（JSON）

动作数据的顶层字段如下（示例动作 `"id": "dao_atk_a"`）：

| 字段 | 类型 | 说明 / 取值 |
|------|------|------|
| `id` | string | 动作标识，示例 `"dao_atk_a"` |
| `group` | string | 招式分组：`dao` \| `jian` \| `quan` \| `anqi` \| `qimen` \| `qiang` \| `neigong` \| `shenfa` |
| `duration` | number | 时长，单位 ms，允许 200~2000 |
| `loop` | boolean | 是否循环，示例 `false`；idle 必须 `true` 且首尾一致 |
| `priority` | number | 优先级：`down 9` > `hit 5` > `cast 3` > `attack 2` > `idle 0`（示例 `2`） |
| `anchors` | object | 挂点：特效只认挂点，不认动作名（子字段见下表） |
| `events` | array | 事件列表：表现用，不参与数值（子字段见下表） |
| `tracks` | array | 轨道列表（子字段见下表） |

`anchors`（挂点）：键为挂点名，值为挂点数组，示例键名 `weaponTip`。

| 字段 | 类型 | 说明 / 取值 |
|------|------|------|
| `anchors.<挂点名>` | array | 挂点数组，示例 `"weaponTip"` |
| `anchors.<挂点名>[].t` | number | 时间，示例 `0.5` |
| `anchors.<挂点名>[].slot` | string | 挂载到哪个 slot，示例 `"weapon"` |
| `anchors.<挂点名>[].x` | number | 相对偏移 x，示例 `0` |
| `anchors.<挂点名>[].y` | number | 相对偏移 y，示例 `52` |
| `anchors.<挂点名>[].angle` | number | 角度，示例 `0` |

`events`（事件）：

| 字段 | 类型 | 说明 / 取值 |
|------|------|------|
| `events[].t` | number | 时间，示例 `0.45` |
| `events[].type` | string | 事件类型，示例 `"hit"` |

`tracks`（轨道）与 `keys`（关键帧）：

| 字段 | 类型 | 说明 / 取值 |
|------|------|------|
| `tracks[].slot` | string | 该轨道驱动的 slot，示例 `"torso"` |
| `tracks[].keys` | array | 关键帧数组 |
| `tracks[].keys[].t` | number | 时间，示例 `0` / `0.3` / `1` |
| `tracks[].keys[].rot` | number | 旋转，示例 `0` / `-0.16` / `0` |
| `tracks[].keys[].ease` | string | 缓动（可选），示例 `"sineOut"` |

**时间写法**：`t ∈ [0,1]` 为归一化（推荐）；`t > 1` 视为毫秒。

**允许的缓动**（只有 5 种，统一手感）：`linear` / `sineIn` / `sineOut` / `quadIn` / `backOut`

**旋转符号约定（易错，务必记住）**：`+y` 向下，**正角度 = 顺时针 = 手臂向前甩到身体左侧（身后）**。
右向角色要「过肩上举」必须用**大负角度**（例：−2.05 rad ≈ −117°），下劈回到小负角度（−0.62 rad ≈ −36°）。

### 每部件关键帧建议

| 部件 | 关键帧数 | 说明 |
|------|:--------:|------|
| torso / pelvis | 4~6 | 主驱动 |
| upperArmR / forearmR | 4~6 | 攻击主表现 |
| head | 3 | 跟随 |
| 腿 | 2~4 | 站姿微调 |
| cloak | 3~4 | 迟滞跟随（比躯干晚 1 帧） |

## 7. 校验规则（编辑器保存前 / CI 全量跑）

| 规则 | 级别 |
|------|:----:|
| slot 必须已注册 | **error** |
| 同一 slot 不得有重复轨道 | **error** |
| 时长 200~2000ms | **error** |
| 循环动作首尾姿态必须一致 | **error** |
| 攻击类动作必须有 `weaponTip`/`palm`/`throwPoint` | **error** |
| 关键帧必须按时间升序、非负 | **error** |
| 挂点引用的 slot 必须存在 | **error** |
| 单轨道关键帧 ≤ 24 | warn |
| 单轨道关键帧 ≥ 2 | warn |

## 8. 新增内容的成本（复利结构）

| 新增 | 需要做的 | 成本 |
|------|----------|:----:|
| 1 门功法 | `gongfa_visual.ts` 加 1 行 | **10 分钟** |
| 1 个伙伴 | 1 套部件贴图（`gen-skin` 自动生成 skin.json） | **1~2 人日** |
| 1 个弟子/敌人 | 复用皮肤 + 换调色板 | **10 分钟** |
| 1 种武器类型 | 1 组动作（8 clip） | **2~3 人日** |
| 1 个特效 | 1 个模板 | **0.5~1 人日** |
