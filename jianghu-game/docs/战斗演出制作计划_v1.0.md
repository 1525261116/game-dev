# 战斗演出制作计划 v1.0

> **对标对象**：`jianghu-references/07_style/战斗演出风格分析_2026-10/`（参考视频：某横版自动回合制群侠手游，41.4 s 抖音录屏）
> **风格一句话**：**冷静的自动战斗 + 高密度的演出爆发** —— 战斗零操作、节奏平稳，每 10~20 s 插入一次 1.2 s 的「黑白水墨 + 书法大字」绝学演出，把"看战斗"变成"看演出"
> **依据**：参考报告 §5.3（架构落地）、§6（落地规范 v0.1）、§7（红线）；本作 GDD `05_combat/战斗方式.md`、`连招系统.md`；`jianghu-game` 五条架构铁律
> **编制日期**：2026-10-12

## 0. 结论先说

| 项 | 结论 |
|----|------|
| **抄什么** | ① 绝学立绘演出的**模板与节奏**；② 出手队列条 + 阵名幡（把战前策略在战中持续可见）；③ 打击反馈三件套（hitstop / 震屏 / 闪白 + 刀光）；④ 飘字信息分层；⑤ **绝学前 BGM 留白** |
| **不抄什么** | ① 怒气/大招资源（我们已移除，且不为此复活）；② 8 位数数值膨胀；③ 全屏运动模糊（移动端做成默认关的开关）；④ 直播展示级的演出密度（每 5 s 一次 → 我们每场 2~4 次） |
| **最大机会** | 我们的**「起势/收势」连招系统**天然是演出触发点：**三连成功（+60% 且吸血）= 绝学演出的语义**，不用新造一套资源。这是本项目独有的"投产比"最高的一件 |
| **分辨率口径** | 参考规范按 1920×1080 写；**我们已把逻辑分辨率提到 1280×720**（2026-10-12，见 `src/render/ui/layout.ts`），空间参数按 **×0.667** 换算；时间参数（ms / s）不变 |
| **前置条件** | 已经就位：三层水墨背景、角色贴图管线、状态图标、战斗日志回放。**缺**：特效层、hitstop、飘字对象池、演出层、音频系统 |

## 2. 架构铁律（不可协商）

| # | 约束 | 落地要求 |
|:-:|------|----------|
| 1 | **演出是表现层事件** | `simulate.ts` **只**输出日志事件；演出由 `comboStage` / `death` 等既有字段驱动。**禁止**在 core 里加任何演出字段 |
| 2 | **结果与演出无关** | 必须有构造用例证明："开启演出 / 关闭演出 / 加速跳过"，`BattleLog` 与 `finalHp` **完全一致** |
| 3 | **零硬编码** | hitstop / 震屏 / 闪白 / 飘字样式 / 演出时长，全部来自 `data/tables/*.csv`，代码只读表 |
| 4 | **可回放** | 演出不得阻塞日志消费；跳过 = 表现层直接消费下一条事件 |
| 5 | **可降级** | 素材缺失时演出退化为"文字标题闪入"，不得黑屏、不得报错（沿用贴图管线的降级策略） |

## 3. 口径换算（**先做这一步，否则整套参数会错 2 倍**）

| 参考规范口径 | 本项目 | 换算 |
|--------------|--------|------|
| 逻辑 1920×1080 | **1280×720** | ×0.667 |
| 站位：中线左右各 640 px | 中线左右各 427 px | ×0.667 |
| 中央留白 x 640–1280 | **x 427–853**（现为中线左右各 160px，可放宽到 427） | ×0.667 |
| 阵幡宽 72 px | **48 px** | ×0.667 |
| 椭圆环 96×36 | **64×24**（现为 78×24） | ×0.667 |
| 飘字字号 34 / 48 / 64 | **23 / 32 / 43** | ×0.667 |
| 状态大字 96 / 128 | **64 / 85** | ×0.667 |
| 震屏幅度 3 / 8 / 16 px | **2 / 5 / 11 px** | ×0.667 |
| hitstop 60 / 100 / 150 ms | 不变 | 时间是绝对量 |
| 演出时长 1.2–1.6 s | 不变 | 同上 |
| BGM / 音效 | 不变 | 同上 |

> **参考视频是 3× 加速录屏**（见报告 §1.3）：视频里 1.0 s 的演出，实时可能是 3.0 s。
> 本计划采用报告 §6.2 已重新定标的**实时口径**（1.2–1.6 s），不再乘 3。

## 4. 分阶段制作计划

### P0 · 舞台地基（0.5 天，无美术依赖）

| 改动 | 文件 | 内容 |
|------|------|------|
| 站位环 | `src/render/scenes/BattleScene.ts` `drawFieldMarks()` | 椭圆投影 → **深色椭圆环**（48×18，alpha 0.35）；入场时 0.3 s 缩放弹出 |
| 中央留白 | 同上 `drawHud()` | tip 文字从画面中央移到**底部边缘**；确保 x 320–640 无常驻 UI |
| 地平线 | `assets/bg/battle/{far,mid,ground}.png` | 美术调整：天空 45% / 地面 55%（地平线约 y=243） |

**验收**：中央 1/3 无任何常驻 UI；站位有"环"而不是"影子"。

---

### P1 · 打击感三件套（1.5 天，**最高性价比，无美术依赖**）

| 改动 | 文件 | 内容 |
|------|------|------|
| 新数据表 | `data/tables/combat_feel.csv`（新） | 直接采用参考库 `落地草案/combat_feel.csv` 的列，按 §3 换算数值；接进现有配置管线（zod + `tables:import`） |
| 表契约 | `src/core/config/schema.ts` | `combatFeelRowSchema` + 跨表校验（事件名白名单） |
| 特效层目录 | `src/render/fx/`（新） | `HitStop.ts` / `ScreenFx.ts` / `SlashFx.ts` |
| hitstop | `HitStop.ts` | **只冻结角色与特效，不冻结飘字与 UI**。实现：角色容器走独立时间轴（累计 delta × 0 的窗口），或用 `scene.time.timeScale` + 飘字用独立 tween 时钟 |
| 闪白 | `ScreenFx.ts` | 全屏矩形插值（白 alpha 0.55→0），PC/移动端统一开启（纯色插值，开销极低） |
| 震屏 | `ScreenFx.ts` | 幅度/时长取表；替换现有硬编码 `shake(130, 0.006)` |
| 刀光 | `SlashFx.ts` | **程序化画弧**（Graphics 二次贝塞尔 + 2~3 层不同 alpha/线宽），无需美术资源即可先跑 |
| 接线 | `BattleScene.perform()` | `damage{crit}` / `miss` / `act{comboStage}` → 按事件名查表取参数 |

**验收**：改 `combat_feel.csv` → 刷新即生效；`crit` 明显比轻击重；关掉开关后表现与现在一致。

---

### P2 · HUD 与信息层（1.5 天，无美术依赖）

| 改动 | 文件 | 内容 |
|------|------|------|
| 出手队列条 | `BattleScene.drawHud()` + 新 `QueueBar.ts` | 按有效身法降序排头像色块；当前行动者高亮；「下一回合」标记 |
| 阵名幡 | 新 `FormationBanner.ts` | 左右竖排：阵名 + 等级 + 生效结果（ok/partial/fail 三色）；**常驻**，替代现在的开局小字 |
| 回合进度 | `drawHud()` | `第 n / 30 回合` |
| 队伍头像条 | 新 `PartyBar.ts` | 底部我方头像 + 血条（复用现有 HP 状态） |
| 中央留空 | `drawHud()` | 复核 §P0 的中央留白规则 |

**验收**：玩家在战斗中随时能看到"我布了什么阵、谁先手、还剩几回合"——对应 GDD「战前策略是核心」。

---

### P3 · 飘字体系 + 特效母题（1.5 天）

| 改动 | 文件 | 内容 |
|------|------|------|
| 飘字 8 类 | 新 `src/render/fx/FloatingText.ts` | 伤害 / 暴击 / 闪避 / 治疗 / **护盾** / **累计统计** / 状态名 / 连招段数；样式取表 |
| 合并规则 | 同上 | 同一目标 **0.25 s 内多次命中合并为一个跳动累加的数字** |
| 对象池 | 同上 | 池 ≥64，同屏上限 24，超出合并（移动端关键） |
| 累计统计 | 同上 | 屏幕中上长驻「总伤害 / 总治疗」（数据来自 `BattleLog.stats`，已有） |
| 特效母题 | `src/render/fx/` | 地面 AoE 环（可直接用**攻击范围可视化**：我们已有 10 型范围数据！）、元素爆发；先用 Graphics 程序化，后续换贴图 |

> **顺手的好处**：我们有 `range`（10 型）数据，**地面范围环可以按真实命中区域绘制** —— 这比参考视频的"元素配色"信息量更大，且零额外成本。

**验收**：同屏 24 条飘字不掉帧；合并规则生效（连续快攻看到的是"跳动累加"而不是刷屏）。

---

### P4 · 绝学立绘演出（**最大记忆点**，2~4 天 + 美术）

| 改动 | 文件 | 内容 |
|------|------|------|
| 演出层 | 新 `src/render/fx/CutIn.ts` | 5 层模板：水墨底 / 墨纹 / 立绘 / 书法大字 / HUD 叠层 |
| 触发规则 | `BattleScene.perform()` | ① `comboStage === 3`（三连）→ 演出，**每场每人 ≤1 次**；② 战局转折（首位队友倒下）→ 每场 ≤1 次；③ 单场总预算 **2~4 次**，间隔 ≥10 s |
| 配置表 | `data/tables/cutin.csv`（新） | 采用参考库 `落地草案/cutin_ultimate.csv`，补 `trigger` 列（`combo3` / `turnaround` / `breakthrough`） |
| 可跳过 | 设置项 | 完整 / 简短（0.6 s 纯标题闪入）/ 关闭；加速 X2·X3 时自动切简短 |
| 不阻塞 | `BattleScene` | 演出期间继续消费日志；伤害在演出结束的同一帧结算并飘字 |
| 资源 | `assets/cutin/`（新） | 见 §5 |

**v0 无立绘版本（建议先做，1 天）**：水墨底用**程序化生成**（黑底 + 白色晕染 + 飞白笔触），标题用**书法字体渲染**，主体先放**现有角色贴图放大 1.8×** —— 这样不用等美术就能验证节奏与手感，也是最好的"给美术看的动态需求"。

**验收**（关键）：构造用例证明"演出开 / 关 / 跳过"三种情况下 `BattleLog`、`finalHp`、`stats` **完全一致**。

---

### P5 · 音频层（2~3 天 + 音频资源）

| 改动 | 文件 | 内容 |
|------|------|------|
| 音频系统 | 新 `src/render/audio/AudioBus.ts` | BGM / 打击音效 / UI 音 三条总线 + 音量设置（本地存档） |
| BGM 留白 | `AudioBus.ts` | 绝学演出前 0.3 s 起降 6~8 dB 或 0.5~1.5 s 留白 —— **参考视频最值得学的音频手法** |
| 打击分层 | `AudioBus.ts` | 轻击（布料+低频 thump）/ 重击（金属+80~150 Hz 冲击）/ 暴击（加一层谐波+短混响） |
| 混音取向 | 资源规范 | 能量集中 1 kHz 以下（移动端喇叭友好）；高频只留刀光/金属 3~6 kHz |
| 加速不变调 | `AudioBus.ts` | X2/X3 只加速打击音效，**BGM 保持原速原调** |

### P6 · 托管与加速（1 天）

## 7. 风险与红线

| 风险 | 对策 |
|------|------|
| **授权红线** | 参考素材是商业游戏直播录屏：**只学方法（模板/节奏/配色/信息分层），不提取任何像素/音频**。书法字体单独确认商用授权 |
| **演出疲劳** | 密度对标"单场 2~4 次"而非参考视频的每 5 s 一次；必须可跳过、加速时自动简短 |
| **时长口径误用** | 只使用 §3 的实时口径；不要直接抄视频里的 1.0 s，也不要 ×3 变成 3.0 s |
| **移动端后处理** | 运动模糊默认**关**（做成画质开关）；闪白用纯色插值 |
| **演出打断结算感** | 演出是"叠层"不是"切场"：HUD 不隐藏、飘字继续滚动、伤害在演出结束同一帧结算 |
| **数值膨胀** | 我们的数值保持 3~5 位可读量级；累计统计做成可选开关（不做 8 位数） |
| **范围蔓延** | 严格按 P0→P6 顺序；**P1 + P3 先做**（无美术依赖、立刻能感知手感），P4 的 v0 版本不立绘即可验证节奏 |

## 8. 建议执行顺序与工作量

| 顺序 | 阶段 | 工作量 | 依赖 | 为什么这个顺序 |
|:----:|------|:------:|------|----------------|
| 1 | **P1 打击感** | 1.5 天 | 无 | 投入产出比最高：不需要任何美术，做完立刻"打得爽" |
| 2 | **P3 飘字 + 范围环** | 1.5 天 | 无 | 信息量提升最明显；范围环可用已有 10 型范围数据，别人没有 |
| 3 | **P2 HUD / 信息层** | 1.5 天 | 无 | 让"战前策略"在战中可见，与 GDD 设计支柱直接对齐 |
| 4 | **P4 v0 演出（无立绘）** | 1 天 | 无 | 先验证节奏与手感；产出"美术需求动态演示" |
| 5 | **P4 完整版演出** | 2~3 天 | 立绘 + 墨纹 + 书法字体 | 最大记忆点，但必须等美术 |
| 6 | **P6 加速/托管** | 1 天 | P4 | 演出与加速的联动收口 |
| 7 | **P5 音频** | 2~3 天 | 音频资源 | 建议与 P4 同步筹备，最后接入 |

**合计**：程序约 **9~11 人日**（不含美术/音频资产）；P1+P3 两步（3 天）即可让战斗"像样"。
